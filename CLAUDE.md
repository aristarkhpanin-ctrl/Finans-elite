## Доинвестирование в актив (пакет №8, gap 1.6) — завершено (AD0–AD2, 0.9.32)

- `Asset.additional_investments: list[AdditionalInvestment(month, amount)]` — модернизация:
  доп. вложение капитализируется (C14 с НДС) и амортизируется от **остаточного срока**
  (`purchase + life − month`). `_assets` переписан на **слоистую амортизацию**: базовый слой
  (`cost/life`) + слой на каждое вложение (`amount/остаток`), все слои заканчиваются вместе
  с активом. Амортизация периода = Σ ставок активных слоёв; остаточная стоимость и выбытие
  при продаже — Σ по слоям; земля слои не амортизирует. **Актив без доинвестиций = один
  базовый слой → числа как прежде** (рефактор проверен: не-версионный дифф golden пуст).
  Бамп 0.9.32; поле пустое по умолчанию. Методика — SPEC §9; план —
  `docs/ADDITIONAL-INVESTMENT-DECOMPOSITION.md`. UI — блок в карточке актива (AssetsTab).

## Детализация стартовых ОС (пакет №8, gap 1.7) — завершено (SO0–SO2, 0.9.37)

- Пред-существующий актив = `Asset` с `purchase_month < 0` (куплен до старта). Капвложений

  (nbv→B14, амортизация→I17), может быть продан. Активы с `purchase_month ≥ 0` дают нулевую
  поправку → числа как раньше (golden только строка версии, бамп 0.9.37). Методика —
  SPEC §9; план — `docs/STARTING-ASSETS-DECOMPOSITION.md`. UI — подсказка к «Месяцу приобретения».

  сетке). Ряд приводится к горизонту `n`, запятая-десятичная/пусто нормализуются; неизвестный
  продукт → не создаётся (v1). UI — кнопки «Шаблон XLSX»/«Импорт XLSX» на вкладке «Сбыт» +
  строка-итог. План — `docs/EXCEL-IMPORT-DECOMPOSITION.md`; 9 unit-тестов (`salesXlsx.test.ts`).

## Доходы подразделений / структура компании (пакет №8, gap 4.5) — завершено (DV0–DV2, 0.9.39)

- `Company.divisions: list[Division(id, name)]` (справочник) + `Product.division_id` (отнесение,
  ≤1 подразделение, None = вне структуры). `compute_division_margins(model, product_margins)`
  **сворачивает маржу продуктов** (пакет №1) по подразделению: выручка, BOM-материалы, сдельная
  ЗП, маржа, доля, число продуктов. **Чистая аналитика поверх `product_margins`** — те же
  соглашения (без фейковой аллокации: продукты без рецептуры/подразделения не входят; висячий
  `division_id` игнорируется; суммовые издержки — «нераспределённые»). `CalcResult.division_margins`
  (пусто без подразделений → в снимок/API не попадает; отчёты, баланс `B20=B34`, golden-числа не
  зависят от подразделений). Бамп 0.9.39; ни один семпл не задаёт подразделения → golden = строка
  версии. Методика — SPEC §6; план — `docs/DIVISIONS-DECOMPOSITION.md`. UI — справочник
  подразделений + селектор на карточке продукта (вкладка «Сбыт»), блок «Доходы подразделений»
  на сводке; DOCX-раздел.

## Второй продукт — «Финанс-Аудит» (анализ фактической отчётности) — в разработке

- Платформа несёт **два продукта**: «Финанс-Элит» (бизнес-план, `calc_core`) и «Финанс-Аудит»
  (анализ факта, `audit_core`). Переключатель в шапке; активный продукт ставит `data-product`
  на `<html>` → тема (зелёная / фиолетовая `#BC13FE`); токены темы — в `styles.css`
  (`:root[data-product="audit"]` + тёмный вариант). Спецификация — `docs/FINANS-AUDIT-SPEC.md`,
  план по этапам A–H — `docs/FINANS-AUDIT-DECOMPOSITION.md`. **Ядро и golden первого продукта
  не затрагиваются.**
- Готово: **Фаза A** (каркас/тема/переключатель), **Фаза B** (`audit_core` модель субъекта/
  периодов/отчётности + инвариант актив=пассив; таблица `audit_subjects` + миграция с RLS;
  CRUD/API `/api/v1/audit/subjects`; фронт — список субъектов + ввод «статья × период»),
  **Фаза C** (аналитика: `audit_core/analysis.py` — аналитическая форма с подытогами,
  горизонтальный/вертикальный анализ, 4 группы коэффициентов; квартал приводится к году,
  нулевая база → `None`; **свой golden аудита** `tests/golden_audit` +
  `UPDATE_AUDIT_GOLDEN=1`; API `…/analyze`; вкладки «Отчёты»/«Коэффициенты»/«Тренды»).
  **Фаза D** (диагностика: `audit_core/diagnostics.py` — модели Альтмана Z′/Z″ по учётным
  величинам + нормативы коэффициентов + сводный «светофор» по последнему периоду; memo-строка
  `M_RETAINED` вне итога пассива; **двухфакторная модель исключена осознанно** — структурно
  не способна подать сигнал риска, см. декомпозицию).
  **Фаза E** (заключение: `audit_core/opinion.py` — детерминированный текст без ИИ, поле
  `opinion` в ответе; DOCX `app/audit_docgen.py` + `GET …/report.docx`; вкладка «Заключение»).
  **Фаза F** (импорт отчётности из Excel: `frontend/src/auditXlsx.ts` — round-trip шаблон,
  матч по коду/названию строки, периоды импорт не меняет; попутно выведена в UI строка
  `M_RETAINED`, без которой диагностика не считалась).
  **Фаза G** (методики: `AuditSubjectModel.user_metrics` — свои показатели-формулы поверх
  аналитической формы, реюз `calc_core.formula`; ошибка формулы не роняет анализ; вкладка
  «Методики» + раздел в DOCX).
  **Фаза H** (консолидация: `audit_core/consolidate.py` — свод по совпадающим подписям
  периодов + анализ группы; **внутригрупповые обороты не исключаются** — предупреждение
  выводится всегда; API `POST …/audit/consolidate`, раздел «Группа»).
  **Все фазы A–H закрыты.** Из v2 сделано: **свои нормативы показателей**
  (`AuditSubjectModel.thresholds` переопределяют универсальные пороги; несогласованный
  порог не применяется молча), **исключение внутригрупповых оборотов** при консолидации
  (`Elimination` — парное вычитание дебиторки/кредиторки и выручки/себестоимости, инвариант
  актив=пассив сохраняется; перебор обрезается с предупреждением), **помесячная
  периодичность** (`kind="month"`; `_PERIOD` в `analysis.py` — одна карта «тип → (дни,
  множитель к году)», множитель задан явно 1/4/12 → месяц ровно ×12, без накопления ошибки)
  и **XLSX-выгрузка таблиц** (`frontend/src/auditExport.ts` — лист на раздел, собирается
  из готового ответа `/analyze`; неопределённый показатель — **пустая ячейка, не ноль**;
  та же выгрузка на своде группы), **сохранённые группы предприятий** (таблица
  `audit_groups` + миграция `c3d5e7f9a1b2` с RLS; API `/api/v1/audit/groups`, свод —
  `…/{id}/analyze`; хранится **состав, а не результат** → числа всегда по текущей
  отчётности; удалённый участник не исчезает молча — назван в оговорке и
  `missing_members`, имя хранится как «надгробие», группа без живых участников даёт
  пустой свод с оговоркой, а не ошибку). Остальное — в декомпозиции.

## Точность движка

- Любое изменение методики расчёта — через golden-master (`UPDATE_GOLDEN=1 pytest
  tests/test_golden.py`) с осознанным ревью диффа чисел + аналитические тесты.
  Балансовый инвариант B20=B34 обязан сходиться (property-тесты, 50 моделей).
- Методика — `docs/CALC-ENGINE-SPEC.md`, план — `docs/ROADMAP.md`.
