# Нормирование процентов по ставке ЦБ — план реализации (N0–N2)

> Пакет №8 gap-анализа (`GAP-ANALYSIS-PE.md` §2.2): проценты по займам вычитаемы в пределах
> норматива (ставка рефинансирования ЦБ × коэффициент), сверхнормативные — за счёт прибыли
> (в I24, налоговую базу не уменьшают). Сейчас — только ручной флаг `interest_on_profit` на
> весь заём. **Изменение методики** → бамп `ENGINE_VERSION`; норматив по умолчанию выключен
> (`cb_refinancing_rate=0`) → golden дрейфует только строкой версии.

## 0. Зафиксированные решения (Q1–Q5)

- **Q1. Параметры** — в `ProjectSettings` (рядом с налогом на прибыль, т.к. правило влияет
  на налоговую базу; хотя gap упоминает «окружение», когезия с налоговым блоком важнее):
  `cb_refinancing_rate: Decimal = 0` (годовая ставка ЦБ; **0 = норматив выключен**) и
  `interest_norm_multiple: Decimal = 1` (законный коэффициент, напр. 1.25/1.5).
- **Q2. Расщепление** — в `_loans`, помесячно, для каждого займа: нормативный процент =
  процент × (norm_m / loan_m), где `norm_m`, `loan_m` — месячные ставки норматива и займа
  (одинаковая конвертация `(1+год)^(1/12)−1`). Вычитаемая часть (→I18) = `min(процент,
  нормативный)`; сверхнорматив (→I24) = остаток. Реализация без пересчёта остатков:
  `ratio = min(1, norm_m/loan_m)`; deductible = `ii·ratio`, excess = `ii·(1−ratio)`.
- **Q3. Взаимодействие с `interest_on_profit`**: заём с флагом «на прибыль» уже целиком в
  I24 (добровольно) — норматив к нему не применяется. Норматив уточняет только вычитаемые
  займы (флаг False): раньше весь процент шёл в I18, теперь I18 (в пределах) + I24 (сверх).
  Валютные займы: сплит в валюте займа, затем пересчёт по `FX[t]` (как весь график).
- **Q4. Выключенный норматив** (`cb_refinancing_rate=0`): `ratio=1` → deductible=весь
  процент, excess=0 → **точно текущее поведение** (I18 весь; заём «на прибыль» — весь I24).
  Golden не дрейфует (кроме версии); ни один семпл не задаёт ставку ЦБ.
- **Q5. Версия/UI** — бамп `0.9.31`; поля в секции «Налоги» вкладки «Проект». Отдельного
  правила ревью не вводим (вне запроса gap).

## 1. Архитектура

```
calc_core/models/project.py   # ProjectSettings: + cb_refinancing_rate / interest_norm_multiple
calc_core/engine/pipeline.py  # _loans(..., norm_monthly): сплит I18/I24 по нормативу
frontend                      # поля в секции «Налоги» GeneralTab
```

## 2. Фазы

- [x] **N0.** Движок: поля модели, сплит процентов в `_loans` по нормативу;
  `ENGINE_VERSION=0.9.31` + регенерация golden (дифф = версия). Тесты: сверхнорматив →
  I24, в пределах норматива → I18, норматив выше ставки займа → весь I18, выключенный
  норматив = текущее поведение, взаимодействие с `interest_on_profit`, валютный заём,
  инвариант B20=B34.
- [x] **N1.** API/UI: openapi + `gen:api`, зеркало `model.ts`, поля «Ставка ЦБ» и
  «Коэффициент норматива» в секции «Налоги»; проверка сборки.
- [x] **N2.** Документация: SPEC §11, ROADMAP, GAP-ANALYSIS (2.2), CLAUDE.md, этот чеклист.

## 3. Инварианты

- `cb_refinancing_rate=0` → числа как раньше (golden = строка версии).
- Сумма I18+I24 по процентам не меняется — меняется только распределение между
  вычитаемыми и невычитаемыми (налоговая база уменьшается на сверхнорматив); касса
  (C24) и остаток долга (B26) не затрагиваются. B20=B34 держится (property-тест).

**Статус: завершено** (0.9.31). v2-направления: помесячная ставка ЦБ (ряд вместо скаляра),
разные нормы для рублёвых и валютных займов, правило ревью «высокая доля сверхнорматива».
