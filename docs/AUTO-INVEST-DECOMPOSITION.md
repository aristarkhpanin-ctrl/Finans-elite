# Автоподбор инвестиций (размещение излишков) — план реализации (I0–I2)

> Пакет №8 gap-анализа (`GAP-ANALYSIS-PE.md` §6): излишки кассы автоматически
> размещаются в депозит — симметрично автоподбору кредита (покрытие дефицита).
> Реюз машинерии депозитов (C8 размещение, C9 доход = I20, тело в B6) — как «синтетический
> депозит». **Изменение методики** → бамп `ENGINE_VERSION`; фича по умолчанию выключена
> (`invest_surplus=False`) → golden дрейфует только строкой версии.

## 0. Зафиксированные решения (Q1–Q6)

- **Q1. Модель** — расширение `AutoFinancing`: `invest_surplus: bool`,
  `invest_annual_rate: Decimal` (ставка депозита). `min_balance` общий: кредит держит
  кассу **не ниже** порога, размещение выметает всё **выше** порога.
- **Q2. Единый решатель** `solve_cash_management(base_flow, opening_cash, min_balance,
  credit_rate, deposit_rate, credit_on, invest_on)` — один прямой проход: проценты по
  кредиту и доход по депозиту начисляются на остатки начала периода; при дефиците — сперва
  изъятие депозита, затем привлечение кредита; при профиците — сперва погашение кредита,
  затем размещение в депозит. **При `invest_on=False` совпадает байт-в-байт с
  `solve_credit_line`** (equivalence-тест) → кредит-only golden без дрейфа.
- **Q3. Инъекция** (`AutoInjection`, симметрично кредиту): депозит — доход в ОПУ
  (`pl_deposit_income` → I20, для налога) отдельно от кассы (`cash_deposit_income` → C9);
  размещение `cash_deposit_placement` → C8 (размещение +, изъятие −); тело `deposit_balance`
  → B6. В пробном прогоне — только P&L-доход (для налога), без кассы; в финальном — оба
  (как процент кредита: I18 в пробном и финальном, C24 — только в финальном).
- **Q4. Итерация** — замкнутый контур теперь по двум рядам: проценты кредита (I18) и доход
  депозита (I20). Невязка = макс. по обоим; демпфирование как прежде. Обратная связь через
  налог (доля < 1) → сходится. Кредит-only: доход депозита ≡ 0, путь итерации не меняется.
- **Q5. Совместимость с ручными депозитами**: авторазмещение аддитивно к ручным
  `financing.deposits` (те уже в base_flow) — управляет остаточным профицитом. Балансовый
  инвариант держится по построению (та же машинерия C8/C9/B6, что у ручных).
- **Q6. Golden** — `invest_surplus` по умолчанию False, ни один семпл не включает →
  инъекция нулевая, пайплайн-обвязка инертна (add с нулями). Бамп `0.9.30`; дифф golden =
  строка версии. Кредит-only golden не дрейфует (тот же путь `solve_credit_line`-логики).

## 1. Архитектура

```
calc_core/models/financing.py     # AutoFinancing: + invest_surplus / invest_annual_rate
calc_core/engine/financing_auto.py# AutoInjection: + 4 депозитных поля; solve_cash_management
calc_core/engine/pipeline.py      # I20/C9/C8/B6 += депозитные добавки авто
calc_core/engine/engine.py        # _solve: единый решатель, итерация по двум рядам
```

## 2. Фазы

- [x] **I0.** Движок: поля модели, `solve_cash_management`, расширение `AutoInjection`,
  обвязка пайплайна, итерация; `ENGINE_VERSION=0.9.30` + регенерация golden (дифф = версия).
  Тесты: equivalence с `solve_credit_line`, размещение излишков (C8/C9/B6), изъятие перед
  кредитом, доход растит налог, оба контура вместе, инвариант B20=B34, сходимость.
- [ ] **I1.** API/UI: openapi + `gen:api`, зеркало `model.ts`, поля в секции

## 3. Инварианты

- `invest_surplus=False` → числа как раньше (golden = строка версии); кредит-only —
  тот же путь решателя (equivalence-тест).
- Депозит-доход → I20 → налог → касса (обратная связь через налог < 1) → сходимость.
- Размещение: касса → B6 (тело), доход → C9 (+I20 → B32); B20=B34 держится (та же
  машинерия, что у ручных депозитов; property-тест).
