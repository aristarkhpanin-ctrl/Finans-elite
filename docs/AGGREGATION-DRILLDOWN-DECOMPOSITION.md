# Агрегация квартал/год и детализация строк (drill-down) — план реализации (G0–G4)

> Пакет №6 gap-анализа (`GAP-ANALYSIS-PE.md` §1.5, §4.2): читабельное отображение длинных
> горизонтов (свёртка отчётных таблиц в кварталы/годы) и раскрытие ключевых строк отчётов
> в составляющие (по продуктам/статьям/активам). **Методика расчёта не меняется**: ядро
> считает помесячно, свёртка — на слое отображения; детализация — сохранение уже
> вычисленных в конвейере слагаемых.

## 0. Зафиксированные решения (Q1–Q6)

- **Q1. Агрегация — только отображение (UI).** Чистый модуль `frontend/src/aggregate.ts`
  — зеркало правил `app/docgen.py` (Q4 пакета №5). Периоды: месяц / квартал / год
  (границы — от старта проекта, как «Год k» в DOCX). Переключатель на странице
  результатов; дефолт по горизонту: `n ≤ 24` — месяц, `n ≤ 72` — квартал, дальше — год.
- **Q2. Правила свёртки** (те же, что в DOCX): потоковые строки — суммы за период;
  баланс — конец периода; C28/P2 — начало периода; C29/P7 — конец; P3 = P2 + ΣP1
  (тождества помесячного отчёта сохраняются). Деньги суммируются в целых копейках
  (строки API → центы → сумма) — без плавающей запятой.
- **Q3. Экспорт не трогаем** (v1): CSV/XLSX/PDF — помесячно, DOCX — по своим правилам
  (Q4 пакета №5). Переключатель влияет только на экранные таблицы отчётов.
- **Q4. Детализация (drill-down)** — новый раздел результата `CalcResult.details`:
  слагаемые ключевых строк, уже вычисленные конвейером (сохранение, не перерасчёт):
  `I1`/`C1` — по продуктам; `C2` — материалы (деньги) по статьям (вкл. синтетические
  BOM, импорт — с таможенным НДС); `C3` — сдельная зарплата (деньги) по статьям;
  `I16` — постоянные издержки (начисление) по статьям (вкл. «Штат: …»; статьи
  «из прибыли» не входят — они в I24); `C14` — по активам с НДС (вкл. этапы
  календарного плана и выкуп лизинга). **I5/I6 не детализируются**: себестоимость
  признаётся через пул готовой продукции (средневзвешенная/FIFO) — пер-строчная
  разбивка была бы фейковой аллокацией. Слагаемые сливаются по имени; полностью
  нулевые пропускаются; пустых кодов нет → модель без данных инертна.
  Инвариант: **Σ слагаемых = строка отчёта** (точно, Decimal).
- **Q5. Golden не дрейфует:** `details` **не входит** в golden-снимок (`serialize.py`) —
  числа уже зафиксированы строками отчётов; корректность (Σ слагаемых = строка отчёта)
  доказывают аналитические тесты. `engine_version` не бампается (методика не меняется).
- **Q6. UI drill-down:** строки отчётов, для которых есть детализация, получают шеврон;
  раскрытие показывает под-строки с именами источников. Агрегация применяется к
  под-строкам теми же правилами (все detail-строки — потоки).

## 3. Инварианты

- Ядро помесячно; свёртка — представление. Тождества годовых/квартальных отчётов
  (C29 = C28 + потоки; P7 = P3 − выплаты; B20 = B34 на конец периода) сохраняются.
- `details` — сохранённые слагаемые уже посчитанных строк; Σ = строка отчёта точно
  (Decimal, без округления при сборе).
