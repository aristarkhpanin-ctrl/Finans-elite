# Импорт рядов продаж из Excel — план реализации (EX0–EX2)

> Пакет №8 gap-анализа (`GAP-ANALYSIS-PE.md` §5.3): PE умеет импортировать данные из Excel.
> У нас был только **экспорт** отчётов (CSV/XLSX/PDF). Добавлен **импорт входных рядов**
> продаж (объём/цена по месяцам) через round-trip XLSX-шаблон. **Только слой фронта/модели —
> расчётного ядра не касается** (golden не затрагивается).

## 0. Зафиксированные решения (Q1–Q4)

- **Q1. Round-trip, а не «слепой» формат.** Приложение само генерирует XLSX-шаблон
  (`Шаблон XLSX`): лист «Продажи», строки `Продукт | Показатель | М1…Мn`, по два ряда на
  продукт — «Объём» и «Цена». Пользователь правит числа в привычном Excel и загружает
  обратно (`Импорт XLSX`). Формат задаёт приложение → нет угадывания структуры.
- **Q2. Сопоставление по имени продукта.** Импорт матчит строки к `operating.sales` по
  **имени продукта** (нормализация: trim + нижний регистр). Обновляются только `volume`/
  `price` совпавших строк; прочие поля строки, продукты и остальная модель не трогаются.
  Продукт из файла без пары в модели → в отчёт `не найдены` (модель не меняется); строка
  с нераспознанным показателем → `пропущено`. **Импорт не создаёт новые продукты** (v1;
  безопаснее — не плодит дубли из опечаток).
- **Q3. Горизонт и числа.** Ряд приводится к длине `n` (обрезка/дополнение нулями);
  запятая-десятичная и пустые ячейки нормализуются (`«80,5» → «80.5»`, пусто → `«0»`).
  Round-trip тождествен: шаблон → импорт → те же ряды.
- **Q4. Клиентский парсинг.** Чтение/запись — в браузере (`read-excel-file` /
  `write-excel-file`, обе грузятся лениво по клику), симметрично существующему экспорту.
  **Бэкенд и ядро не задействованы**, `ENGINE_VERSION`/golden не меняются.

## 1. Архитектура

```
frontend/src/salesXlsx.ts             # чистые: buildSalesTemplate (грид), applySalesRows
                                      # (наложение разобранных строк на план); тонкие
```

## 2. Фазы

- [x] **EX0.** Чистые функции + парсер: `buildSalesTemplate(operating, n)` (грид продукт ×
  месяц, ряды «Объём»/«Цена»), `applySalesRows(operating, rows, n)` (иммутабельное наложение,
  отчёт `matched/skipped/ignored`), обёртки `downloadSalesTemplate`/`parseSalesXlsx`. 9 unit-
  тестов (round-trip, матч по имени без регистра, обрезка/дополнение, запятая/пусто,
  неизвестный продукт, чужой показатель, заголовок).
- [x] **EX1.** UI: кнопки «Шаблон XLSX» (скачать) и «Импорт XLSX» (скрытый file-input) в
  шапке вкладки «Сбыт»; применение результата к модели через `onChange` + строка-итог
  (обновлено/не найдены/пропущено). `tsc` + `build` + vitest (64) зелёные.
- [x] **EX2.** Документация: GAP-ANALYSIS (5.3 ✅), ROADMAP, CLAUDE.md, PROJECT-STATUS, чеклист.

## 3. Инварианты

- Импорт правит только `volume`/`price` совпавших по имени строк продаж — ядро, отчёты и
  golden не затрагиваются (чистая правка входной модели, как ручной ввод в сетке).
- Ничего не сопоставлено → модель возвращается той же ссылкой (нет ложного «изменено»).
- Round-trip тождествен: `Шаблон XLSX` → правка → `Импорт XLSX` без правок = те же ряды.

**Статус: завершено** (без бампа `ENGINE_VERSION` — ядро не изменено). v2-направления:
импорт прямых/постоянных издержек и производства; создание новых продуктов из файла (с
подтверждением); импорт по `product.id`, а не только имени; экспорт готового шаблона с
подсказками-комментариями; загрузка CSV как альтернатива XLSX.
