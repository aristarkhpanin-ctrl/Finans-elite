# Настраиваемые налоги — план реализации (T0–T2)

> Gap 2.1 (`GAP-ANALYSIS-PE.md`): произвольные налоги как в PE — название, ставка,
> база (выручка/ФОТ/имущество/прибыль/**формула**), периодичность уплаты
> (месяц/квартал/год → `B21`), отнесение (вычитаемые/за счёт прибыли). Строится на
> заготовке `Tax` в `models/environment.py` и языке формул (пакет №4).
> **Изменение методики** → бамп `ENGINE_VERSION` (0.9.28); пустой список налогов
> инертен → golden дрейфует только строкой версии.

## 0. Зафиксированные решения (Q1–Q7)

- **Q1. Модель** — расширение заготовки `Environment.taxes: list[Tax]`:
  `Tax(name, rate, base, formula, periodicity, allocation)`. `base`:
  `revenue | payroll | property | profit | formula`; `periodicity`:
  `month | quarter | year`; `allocation`: `expense | profit`. Литеральные типы
  (enum в openapi → селекты в UI).
- **Q2. Базы — «до настраиваемых налогов»** (разрыв циклов, один детерминированный
  проход): базы вычисляются по **предварительному прогону** конвейера без настраиваемых
  налогов и без автоподбора финансирования; затем налоги инъецируются в основной расчёт
  (включая все итерации автоподбора — налоги влияют на потребность в деньгах).
  Пресеты выражены формулами над строками предварительного прогона:
  `revenue → I1`; `payroll → I6+I13+I14+I15` (загруженный ФОТ, вкл. взносы);
  `property → B13+B14` (амортизируемое имущество, как база I9);
  `profit → МАКС(I26, 0)` (положительная налогооблагаемая прибыль);
  `formula` — произвольная формула пользователя (тот же вычислитель, DoS-лимиты).
- **Q3. Начисление** = база × ставка, помесячно, без округления (Decimal). Знак не
  зажимается (формульная база может дать отрицательный ряд — ответственность автора
  модели; документировано).
- **Q4. Отнесение**: `expense` → `I21` (другие издержки, уменьшают налоговую базу
  прибыли); `profit` → `I24` (за счёт прибыли, не уменьшают). «В себестоимость» и
  «в цену» — v2.
- **Q5. Уплата и `B21`**: месяц — в месяце начисления (как профильные налоги v0);
  квартал/год — в **последнем месяце периода проекта** (t%3==2 / t%12==11)
  накопленным итогом. Неуплаченный остаток (хвост неполного периода) честно висит
  в `B21` (отсроченные налоговые платежи — суммируется с отложенным НДС);
  принудительного закрытия в конце горизонта нет. Деньги — `C12`.
- **Q6. Ошибка формулы базы — `ModelError`** (422 с именем налога): молча нулевой
  налог в финансовом продукте недопустим (в отличие от таблиц пользователя, где
  ошибка строки безвредна).
- **Q7. Детализация `C12`** (синергия с пакетом №6): слагаемые — профильные налоги
  (налог на прибыль/имущество/с продаж/НДС) + каждый настраиваемый налог по имени;
  Σ = C12 точно. Пустой набор — как раньше (код появляется при ненулевых слагаемых).

## 1. Архитектура

```
calc_core/models/environment.py  # Tax: + formula/periodicity/allocation (Literal)
calc_core/engine/taxes.py        # TaxInjection + compute_custom_taxes(model, pass1-отчёты)
calc_core/engine/pipeline.py     # инъекция: I21/I24 (+ C12, B21) + детализация C12
calc_core/engine/engine.py       # _solve: предварительный прогон → инъекция во все прогоны
```

## 3. Инварианты

- Пустой `environment.taxes` → предварительный прогон не выполняется, инъекция
  отсутствует → числа как раньше (golden меняется только строкой `engine_version`).
- Балансовый инвариант: начислено − уплачено = прирост `B21`; уплата уменьшает `B1`;
  начисление проходит через прибыль (I21/I24 → I28 → P7 → B32) — B20=B34 сходится
  (property-тесты).
