# Финанс-Аудит — спецификация продукта №2 (анализ финансового состояния)

> Второй продукт платформы: **Финанс-Аудит** — анализ и диагностика финансового состояния
> предприятия по его **фактической** отчётности (ретроспектива). Функциональный ориентир —
> Audit Expert (Эксперт Системс), «зеркальный брат» Project Expert; **реализация — своя, с
> нуля, по общеизвестной методологии финансового анализа** (коэффициенты, Z-счёт Альтмана и
> т.п. — публичные формулы). Проприетарный код/данные Audit Expert не используются.
>
> Статус: **черновик спецификации (шаг 1)**. Код ещё не пишется — это карта: что делаем, что
> переиспользуем из готового каркаса Финанс-Элит, что строим заново, архитектура двух
> продуктов на одном сайте и визуальная тема (фиолетовая).

## 0. Позиционирование: два продукта на одной платформе

| | **Финанс-Элит** (продукт №1) | **Финанс-Аудит** (продукт №2) |
|---|---|---|
| Аналог | Project Expert | Audit Expert |
| Задача | Планирование **вперёд** (бизнес-план, прогноз) | Диагностика **факта назад** (анализ состояния) |
| Вход | Модель проекта (продажи, издержки, инвестиции) | **Готовая бухотчётность** за периоды |
| Ядро | `calc_core`: модель → 4 прогнозных отчёта → показатели | `audit_core`: факт-отчёты → анализ → диагностика → заключение |
| Выход | NPV/IRR, отчёты, оценка бизнеса | Коэффициенты, тренды, риск банкротства, рейтинг, заключение |

**Общая платформа** (не дублируется): авторизация, организации/биллинг, UI-каркас и
UI-кит, движок коэффициентов, отчёты/графики, экспорт (DOCX/XLSX/CSV/PDF), ревью-заключение,
версии, консолидация групп, дисциплина точности (Decimal + golden-master). Пользователь на
сайте **выбирает продукт** («Бизнес-план» / «Аудит»), тема переключается (зелёная ↔ фиолетовая).

## 1. Функциональный объём Финанс-Аудит

Модули (ориентир — Audit Expert; реализация своя):

1. **Ввод фактической отчётности по периодам** — баланс (актив/пассив) и отчёт о финансовых
   результатах (ОПУ) за несколько периодов (год/квартал); далее — ОДДС. Ручной грид + импорт
   из Excel + шаблоны РСБУ (форма 1 / форма 2).
2. **Приведение к единой аналитической форме** — переклассификация «сырых» статей в наш
   канонический каталог кодов (`B*` баланс, `I*` ОПУ); контроль сходимости `актив = пассив`
   (инвариант `B20 = B34`, уже есть). Переоценка статей / формат МСФО — v2.
3. **Горизонтальный анализ** — изменение статей к предыдущему периоду (абсолют и темп роста).
4. **Вертикальный анализ** — структура (доля статьи в итоге баланса/выручке) по периодам.
5. **Финансовые коэффициенты** — ликвидность, платёжеспособность, финансовая устойчивость,
   рентабельность, деловая активность (5 групп — **движок уже есть**, переориентируется на факт).
6. **Диагностика риска банкротства / платёжеспособности** — открытые скоринговые модели
   (Z-счёт Альтмана в модификациях и аналоги; регламентные методики РФ). Оценка «светофором».
7. **Бенчмаркинг** — сравнение с нормативами и между периодами/предприятиями, рейтингование.
8. **Пользовательские методики** — свои показатели/аналитические таблицы/выводы (**реюз языка
   формул и «таблиц пользователя»**).
9. **Экспертное заключение** — детерминированный авто-текст по результатам (**реюз/адаптация
   ревью-движка `build_opinion`**).
10. **Консолидация группы предприятий** («Интегратор») — свод отчётности группы (**реюз
    машинерии холдингов**).
11. **Экспорт** — DOCX (заключение + таблицы), XLSX/CSV/PDF (**реюз**).

## 2. Модель данных (вход)

- **Субъект анализа** (предприятие): реквизиты, валюта, отрасль (для нормативов).
- **Периоды**: список отчётных дат (год/квартал), упорядочены; аналог «горизонта» первого
  продукта, но это факт, а не прогноз.
- **Отчёты по периодам**: баланс и ОПУ как ряды по периодам. Ввод — грид «статья × период»
  (аналог `MonthlyGrid` → `PeriodGrid`), импорт из Excel (расширение подхода `salesXlsx.ts`),
  шаблоны РСБУ.
- **Аналитическая форма**: маппинг введённых статей в канонические коды `B*/I*`. Тот же
  инвариант сходимости баланса, что и в первом продукте — гарантия корректности ввода.

## 3. Методика (ядро `audit_core`)

- **Чистые детерминированные функции над фактическими отчётами** (как `calc_core`): `Decimal`,
  фиксированный контекст, golden-master на эталонных наборах. Никакого прогноза — только
  преобразования и показатели над введёнными числами.
- **Коэффициенты**: те же формулы 5 групп, но на фактических рядах по периодам.
- **Горизонтальный/вертикальный анализ**: производные представления (Δ к прошлому периоду,
  темп, доля в итоге) — чистая арифметика над отчётами.
- **Диагностика банкротства**: публичные модели (Альтман Z, и т.п.) как отдельные правила с
  числовым обоснованием (по образцу правил ревью — `Finding` с `evidence`).
- **Заключение**: авто-текст над фактами (интро по «светофору», ключевые показатели, находки,
  вердикт) — адаптация `build_opinion`.

## 5. Что строим заново

1. Модель субъекта/периодов/фактических отчётов + маппинг в аналитическую форму.
2. Ядро `audit_core` (горизонтальный/вертикальный анализ; переиспользование коэффициентов).
3. Диагностика банкротства (открытые скоринги) + нормативные методики.
4. Бенчмаркинг/нормативы отрасли.
5. Импорт форм РСБУ (форма 1/2) из Excel.
6. Продуктовый переключатель на сайте + фиолетовая тема.

## 6. Архитектура двух продуктов

- **Backend.** Новое чистое ядро `backend/audit_core/` **рядом** с `calc_core/`, оба стоят на
  общем фундаменте (`money`/Decimal, `series`, каталог строк отчётов, `ratios`, ревью). Общий
  слой `app/` (auth, organizations, billing, export) обслуживает оба продукта. Новые роуты под
  префиксом `/api/v1/audit/...`.
- **БД.** Новые таблицы (`audit_subjects`, `audit_statements`, `audit_analyses`, версии) с RLS
  по `org_id` — ровно как `projects`/`project_versions`.
- **Frontend.** Общий UI-кит и компоненты; два рабочих пространства (бизнес-план / аудит) и
  **экран выбора продукта** (лендинг/переключатель в шапке). Роутинг: `/projects…` (продукт 1),
  `/audit…` (продукт 2).
- **Разделение ядер:** `calc_core` (прогноз) и `audit_core` (факт) независимы; **golden-мастер
  Финанс-Элит не затрагивается** — второй продукт не меняет методику первого.

## 7. Визуальная тема: зелёный → фиолетовый

- **Та же дизайн-система**, сдвигается только палитра акцента: зелёный акцент и зелёные
  градиенты → **фиолетовые**. Формы, компоненты, типографика, сетки — без изменений.
- **Реализация через токены** (единый источник — объект `THEME()` / CSS-переменные): продукт
  задаёт набор акцентных токенов (`--accent`, `--accent-2`, градиенты, `--chart-1..7`).
  Финанс-Элит — зелёный набор, Финанс-Аудит — фиолетовый; активный продукт ставит `data`-атрибут
  на корне, значения токенов переключаются. **Дублирования CSS нет** — один набор классов,
  разные значения переменных.
- Продуктовый переключатель — в шапке и/или на стартовом экране; тема следует за выбором.

## 8. Дорожная карта (фазы; каждая — своя декомпозиция + отдельный коммит)

- [ ] **A. Каркас продукта и тема.** Фиолетовые токены как второй набор темы; продуктовый

## 10. Правовая чистота

Реализация — стандартная, общеизвестная методология финансового анализа (коэффициенты,
Z-счёт Альтмана и пр. — публичные формулы). **Проприетарный код, данные и бинарники Audit
Expert не используются.** Дистрибутивы Audit Expert (пиратские папки в репозитории) подлежат
удалению (отдельный коммит) — для разработки собственного продукта они не нужны.

## Приложение А. Аналитическая форма: маппинг РСБУ → коды отчётов

Целевая аналитическая форма — **тот же канонический каталог**, что в Финанс-Элит: баланс
`B1–B34` (итог актива `B20`, итог пассива `B34`, инвариант `B20=B34`), ОПУ `I1–I28`.
Ввод «сырой» РСБУ-отчётности отображается (маппится) в эти коды.

**Форма 1 (Бухгалтерский баланс) → коды `B*`:**

| Раздел РСБУ | → аналитические коды |
|---|---|
| I. Внеоборотные активы | `B11` ОС (остаточная), `B16` НМА/прочие, `B18` фин. вложения |
| II. Оборотные активы | `B3` запасы сырья, `B4` НЗП, `B5` ГП, `B2` дебиторка, `B1` деньги, `B6` краткосрочные фин. вложения, `B7` РБП |
| **Итог актива** | **`B20`** |
| III. Капитал и резервы | `B27`/`B29` уставный/сверх номинала, `B30` резервы, `B31` добавочный/переоценка, `B32` нераспределённая |
| IV. Долгосрочные обязательства | `B26` |
| V. Краткосрочные обязательства | `B22` займы, `B23` кредиторка, `B24` авансы, `B21` отложенные |
| **Итог пассива** | **`B34`** (контроль `B20=B34`) |

**Форма 2 (Отчёт о фин. результатах) → коды `I*`:**

| Строка РСБУ | → код |
|---|---|
| Выручка | `I1` (→ `I4` чистый объём) |
| Себестоимость продаж | `I5` (`I7` суммарные прямые) |
| Валовая прибыль | `I8` |
| Коммерческие + управленческие расходы | `I10`/`I12` (`I16` суммарные постоянные) |
| Проценты к уплате | `I18` |
| Прочие доходы/расходы | `I20`/`I21` |
| Прибыль до налогообложения | `I23` |
| Налог на прибыль | `I27` |
| Чистая прибыль | `I28` |

Маппинг задаётся таблицей соответствия (редактируемой), значения вводятся по периодам;
контроль `актив = пассив` — как в первом продукте.

## Приложение Б. Перечень аналитических показателей v1

**Коэффициенты (движок `reports/ratios.py` — переиспускается на фактических рядах):**

- **Ликвидность:** коэф. текущей ликвидности, коэф. срочной (быстрой) ликвидности, чистый
  оборотный капитал.
- **Деловая активность (оборачиваемость):** периоды оборота запасов / дебиторки / кредиторки
  (дни); оборачиваемость рабочего капитала, основных средств, активов.
- **Финансовая устойчивость (структура капитала):** суммарные обязательства к активам, к
  собственному капиталу; коэффициент покрытия процентов.
- **Рентабельность:** валовой, операционной, чистой прибыли; ROA (рентабельность активов),
  ROE (рентабельность собственного капитала).
- **Инвестиционные:** прибыль на акцию (EPS), дивиденды на акцию, покрытие дивидендов,
  сумма активов на акцию.

**Горизонтальный анализ** (по каждой строке отчёта, для периода `t>0`): абсолютное
изменение `Δ = X[t] − X[t−1]` и темп `X[t]/X[t−1] − 1`.

**Вертикальный анализ** (структура): доля строки в базовом итоге — для баланса база `B20`
(суммарный актив), для ОПУ база `I1` (выручка).

## Приложение В. Диагностика банкротства (открытые модели, v1)

Публичные скоринговые модели финансовой устойчивости (общеизвестные академические формулы);
считаются над аналитической формой, результат — числовой балл и зона «светофора».

- **Z-счёт Альтмана (5-факторный, для публичных компаний).** Линейная свёртка пяти
  относительных показателей: рабочий капитал/активы, нераспределённая прибыль/активы,
  EBIT/активы, капитал/обязательства, выручка/активы. Зоны риска: низкая устойчивость /
  неопределённость / устойчивость (пороги — из опубликованной модели).
- **Z′-модель Альтмана (для непубличных компаний).** Та же структура с балансовой стоимостью
  капитала и своими коэффициентами/порогами.
- **2-факторная модель** — простой индикатор (текущая ликвидность + доля заёмных средств).

«Светофор» риска = зона по основному Z-баллу. Модели оформляются как правила с числовым
обоснованием (по образцу правил ревью — `Finding` + `evidence`), поэтому расширяемы.
(v2: Таффлер, Бивер, регламентные методики РФ, отраслевые пороги.)

## Приложение Г. Структура экспертного заключения

Детерминированный авто-текст (адаптация `build_opinion`), над фактами анализа:

1. **Интро по «светофору»** финансового состояния (устойчиво / зона внимания / риск).
2. **Ключевые показатели и динамика** — итоговые коэффициенты по группам, тренды за периоды.
3. **Находки** — слабые/выходящие за нормативы коэффициенты, отрицательная динамика, зона
   риска банкротства (топ по значимости, с числовым обоснованием).
4. **Вердикт** — сводная оценка финансового состояния и устойчивости.

Без ИИ — шаблонные формулировки над числами (как заключение первого продукта).
