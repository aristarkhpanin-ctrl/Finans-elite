# Finans-Elite — статус проекта (обзор)

> Единая карта состояния: что сделано, что осознанно отложено в v2, что внешне
> заблокировано. Сводит серию пакетов расширения методики (движок `0.9.15 → 0.9.39`) и второй
> продукт — «Финанс-Аудит». Источники: `ROADMAP.md`, `CALC-ENGINE-SPEC.md`,
> `FINANS-AUDIT-SPEC.md` и `*-DECOMPOSITION.md` по каждому пакету. Обновлять при
> завершении пакета.

## 1. Текущее состояние

- **Два продукта на одной платформе:** «Финанс-Элит» (бизнес-план, `calc_core`) и
  «Финанс-Аудит» (анализ факта и due diligence фирмы-цели, `audit_core`). У каждого свой
  каталог тарифов и **свой golden-снимок** (`tests/golden`, `tests/golden_audit`).
- **Расчётное ядро:** `engine_version 0.9.39` (предварительная 0.x — пока открыты
  методические вопросы SPEC §22).
  Помесячное, на `Decimal`, 4 отчёта (ОПУ/Кэш-фло/Баланс/Использование прибыли).
- **Инвариант** `B20=B34` (и `B1=C29`, `B32=P7`) держится: property-тест на 50 случайных
  моделях по всем фичам + golden-master (4 эталонных проекта, дифф чисел под ревью).
- **Тесты:** backend 1018 passed / 3 skipped (pytest), frontend 675 passed (vitest),
  3 сквозных прохода Playwright (`npm run e2e`); ruff + mypy (scope `calc_core`) +
  `tsc --noEmit` + `npm run build` — зелёные.
- **Дисциплина точности:** любое изменение методики → бамп `ENGINE_VERSION` +
  `UPDATE_GOLDEN=1 pytest tests/test_golden.py` + проверка «не-версионный дифф пуст»
  (новые фичи по умолчанию инертны → golden дрейфует только строкой версии). Новые правила
  ревью — golden-тест на срабатывание и тишину.
- **Дисциплина слоёв due diligence:** каждый пакет «Финанс-Аудита» — чистая функция
  **над** `AuditResult`, а не его расширение; ни один не входит в снимок, поэтому
  `golden_audit` не сдвинулся ни разу за все фазы. Разбор дела считается **одним
  конвейером** (`audit_core/pipeline.py`), общим для экрана, документа и выгрузки.

## 3. Функциональный охват

Закрыты все разделы методики, ради которых ядро задумывалось:

- **Ядро/методика:** помесячный расчёт на `Decimal`, 4 отчёта, двойной слой
  (начисление/оплата), валюты и курсовая разница, инфляция рядами по годам, активы
  (в т.ч. НМА, пред-существующие, доинвестирование), лизинг с выкупом и страхованием.
- **Окружение и налоги:** профильные налоги, настраиваемые налоги с формулой базы,
  периодичность уплаты, нормирование процентов по ставке ЦБ.
- **Операционный план:** сбыт со схемами оплаты и пер-строчным НДС, производство и
  запасы, материалы и BOM, персонал, календарный план с бюджетом по этапам.
- **Финансирование и анализ:** займы, капитал, дивиденды, автоподбор кредита и
  размещения излишков, показатели эффективности (в т.ч. во второй валюте), доходы
  участников и подразделений, чувствительность, Монте-Карло, what-if, оценка бизнеса.
- **Отчётность и экспорт:** агрегация квартал/год, drill-down строк, DOCX-бизнес-план,
  XLSX-выгрузки, импорт рядов продаж из Excel, печатные формы.

## 4. Осознанно отложено в v2

Из «v2-направления» декомпозиций (не тихие пропуски — зафиксированы с мотивировкой):

- **Инфляция ОС/capex** — индексация стоимости активов (синтетические активы делают
  индексацию контрактных сумм неоднозначной); помесячные ряды инфляции.
- **Налоги:** отнесение «в себестоимость»/«в цену»; периодичность имущества/налога с продаж;
  правило ревью «высокая доля сверхнорматива процентов».
- **Активы:** отдельная строка НМА в балансе (не B16); доинвестиция, продлевающая срок;
  нелинейные методы амортизации; автобалансировка стартовых ОС капиталом.
- **Доходы участников:** кредитная линия автоподбора/лизингодатели/привилегированные акции
  как участники; автовыбор инструментов размещения излишков.
- **Версии/актуализация:** автоснимок версии при финализации; диф отчётных строк; статус
  этапа (не начат/в работе/завершён), % выполнения, факт помесячных потоков этапа.
- **Формулы/агрегация:** Тенденция/Нормировать, ссылки между строками таблиц; агрегация в
  экспортных файлах (CSV/XLSX/PDF), детализация C5/C6/C12, полугодие как период.
- **«Финанс-Аудит»:** рыночные медианы мультипликаторов и подбор сделок-аналогов (базы
  сделок нет — сравнение идёт только с ориентирами самой организации, Прил. Ф);
  24 автопроцедуры по первичным документам, сценарии с вероятностями, сводный балл,
  рекомендация по сделке (перечислены на самих экранах, чтобы отсутствие не читалось как
  благополучие); полная трансформация отчётности РСБУ ↔ МСФО (нужна детальная форма
  ввода и профессиональные суждения, а не пересчёт агрегатов).

## 5. Условие фиксации 1.0

**Открытые методические вопросы** (`SPEC §22`, ROADMAP A10) — места, где общепринятая
методика допускает несколько трактовок: проводка I24, момент признания НДС, курсовая
разница I25, график инвестиций, автоподбор, коэффициенты, перенос убытков, оценка
запасов. Все они **реализованы и покрыты тестами**; открыт не расчёт, а выбор трактовки,
и подтверждать его следует на реальных проектах и профессиональным суждением бухгалтера
или аудитора. До этого версия держится как `0.x` (предварительная).

## 6. Как поддерживается точность

- Методика — `CALC-ENGINE-SPEC.md`; каждый пакет — отдельная декомпозиция с
  зафиксированными решениями (Q1…Qn) и фазами, каждая фаза = отдельный коммит.
- Пустые/выключенные по умолчанию новые сущности инертны → числа существующих моделей
  не дрейфуют (golden = строка версии); методические правки проходят ревью диффа чисел.
- Новые разделы результата сериализуются в снимок только при непустом содержимом
  (budget/product_margins/user_tables/participants); `details` — вне снимка (держат
  аналитические тесты).
- Ввод числа нормализуется **на одной границе** (`calc_core/decimals.py`): русское
  написание «1 200,50» принимается, неоднозначное — отклоняется как прежде. Разбор ввода
  на числа не влияет, поэтому `ENGINE_VERSION` при этом не бампится (SPEC §3).
