## 1. Текущее состояние

- **Расчётное ядро:** `engine_version 0.9.37` (предварительная 0.x — до сверки по эталону).
  Помесячное, на `Decimal`, 4 отчёта (ОПУ/Кэш-фло/Баланс/Использование прибыли).
- **Инвариант** `B20=B34` (и `B1=C29`, `B32=P7`) держится: property-тест на 50 случайных
  моделях по всем фичам + golden-master (4 эталонных проекта, дифф чисел под ревью).
- **Тесты:** backend ~550 passed (pytest), frontend 55 passed (vitest); ruff + mypy
  (scope `calc_core`) + `tsc --noEmit` + `npm run build` — зелёные.
- **Дисциплина точности:** любое изменение методики → бамп `ENGINE_VERSION` +
  `UPDATE_GOLDEN=1 pytest tests/test_golden.py` + проверка «не-версионный дифф пуст»
  (новые фичи по умолчанию инертны → golden дрейфует только строкой версии). Новые правила
  ревью — golden-тест на срабатывание и тишину.

## 4. Осознанно отложено в v2

Из «v2-направления» декомпозиций (не тихие пропуски — зафиксированы с мотивировкой):

- **Инфляция ОС/capex** — индексация стоимости активов (синтетические активы делают
  индексацию контрактных сумм неоднозначной); помесячные ряды инфляции.
- **Налоги:** отнесение «в себестоимость»/«в цену»; периодичность имущества/налога с продаж;
  правило ревью «высокая доля сверхнорматива процентов».
- **Активы:** отдельная строка НМА в балансе (не B16); доинвестиция, продлевающая срок;
  нелинейные методы амортизации; автобалансировка стартовых ОС капиталом.
- **Доходы участников:** кредитная линия автоподбора/лизингодатели/привилегированные акции
  как участники; автовыбор инструментов размещения излишков.
- **Версии/актуализация:** автоснимок версии при финализации; диф отчётных строк; статус
  этапа (не начат/в работе/завершён), % выполнения, факт помесячных потоков этапа.
- **Формулы/агрегация:** Тенденция/Нормировать, ссылки между строками таблиц; агрегация в
  экспортных файлах (CSV/XLSX/PDF), детализация C5/C6/C12, полугодие как период.

## 5. Внешне заблокировано (условие 1.0)

**Сверка методики по эталону** (`SPEC §22`, ROADMAP A10): точная сверка чисел с выходами
Project Expert 7.21 на тестовых проектах перед фиксацией `engine_version 1.0`. Требует
**самих эталонных выгрузок PE** (которых нет в распоряжении). До этого версия держится как
`0.x` (предварительная). Открытые к сверке нюансы перечислены в SPEC §22 (проводка I24,
момент признания НДС, курсовая разница I25, график инвестиций, автоподбор, коэффициенты,
перенос убытков, оценка запасов) — реализованы, но не сверены построчно с оригиналом.

## 6. Как поддерживается точность

- Методика — `CALC-ENGINE-SPEC.md`; каждый пакет — отдельная декомпозиция с
  зафиксированными решениями (Q1…Qn) и фазами, каждая фаза = отдельный коммит.
- Пустые/выключенные по умолчанию новые сущности инертны → числа существующих моделей
  не дрейфуют (golden = строка версии); методические правки проходят ревью диффа чисел.
- Новые разделы результата сериализуются в снимок только при непустом содержимом
  (budget/product_margins/user_tables/participants); `details` — вне снимка (держат
  аналитические тесты).
