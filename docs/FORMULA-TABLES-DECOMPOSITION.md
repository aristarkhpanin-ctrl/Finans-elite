# Язык формул и таблицы пользователя — план реализации (F0–F5)

> Пакет №4 gap-анализа (`GAP-ANALYSIS-PE.md` §4.1): ключевая фича гибкости PE — ~40 функций
> над помесячными рядами, произвольные пользовательские таблицы. Формат — как ревью (R) и
> календарный план (K): фазы F0–F5, каждая = отдельный коммит; движок отчётов не трогаем
> (таблицы считаются **после** расчёта, как ревью), golden без дрейфа (пустые таблицы
> инертны).

## 0. Зафиксированные решения (Q1–Q6)

- **Q1. Синтаксис.** Арифметика `+ − * / ^`, скобки, сравнения `< > <= >= == !=` (дают
  0/1), унарный минус, вызовы `ФУНК(а, б)`. Идентификаторы — **коды строк отчётов**
  (`I1…I28`, `C1…C29`, `B1…B34`, `P1…P7`, регистронезависимо) и константа `N` (горизонт).
  Разделитель аргументов — запятая ⇒ десятичный разделитель в числах — **точка**.
- **Q2. Безопасность.** Собственный токенизатор + рекурсивный парсер + вычислитель на
  Decimal (никакого `eval`). Лимиты: длина формулы ≤ 500 символов, ≤ 200 узлов AST,
  глубина ≤ 32 (DoS-защита). Синтаксические/типовые ошибки → ошибка строки таблицы
  (расчёт не падает, ряд нулей + сообщение). **Поэлементное деление на 0 → 0**
  (финмодельная семантика пустых месяцев; документировано).
- **Q3. Типы и broadcast.** Значение = ряд длины `n` либо скаляр; скаляр автоматически
  расширяется до ряда в поэлементных операциях. Свёртки (`SUM`, `NPV`, `IRR`, …) дают
  скаляр.
- **Q4. Набор функций v1** (латинские имена + русские алиасы, регистронезависимо):
  `SHIFT/СДВИГ(x, k)`, `CUM/АККУМ(x)`, `DIFF/РАЗН(x)`, `DISCOUNT/ДИСК(x, ставка_год)`,
  `NPV/ЧПС(x, ставка_год)`, `IRR/ВНД(x)`, `SUM/СУММ(x)`, `AVG/СРЗНАЧ(x)`,
  `MIN/МИН(x[, y])`, `MAX/МАКС(x[, y])` (1 аргумент — свёртка-скаляр, 2 — поэлементно),
  `ABS/МОДУЛЬ(x)`, `ROUND/ОКРУГЛ(x[, знаков])`, `POW/СТЕПЕНЬ(x, p)`, `EXP(x)`, `LN(x)`,
  `IF/ЕСЛИ(усл, а, б)` (поэлементно), `ELEM/ЭЛЕМЕНТ(x, t)` (скаляр), `PART/ЧАСТЬ(x, от, до)`
  (вне диапазона — нули). Расширение v2: Тенденция, Нормировать, объединение в периоды.
- **Q5. Таблицы.** `ProjectModel.user_tables: list[UserTable(id, name, rows[UserRow(name,
  formula)])]`. Считаются **после** расчёта над готовым результатом (`CalcResult.user_tables`);
  ошибочная строка получает `error` и нули — расчёт отчётов не зависит от формул. Ссылок
  между строками таблицы в v1 нет (v2).
- **Q6. Снимок/совместимость.** `user_tables` в golden-снимок — только при непустых
  таблицах; пустые (по умолчанию) инертны → golden без дрейфа. Настраиваемые налоги на базе
  формул (gap 2.1) — отдельный пакет поверх этого.

## 1. Архитектура

```
calc_core/formula/            # чистая подсистема (как review/)
  __init__.py                 # evaluate(expr, env, n) → Series|Scalar; FormulaError
  parser.py                   # токенизатор + рекурсивный парсер → AST (с лимитами)
  functions.py                # реестр функций (имя → арность + реализация)
  evaluator.py                # вычислитель AST над окружением
calc_core/models/tables.py    # UserTable/UserRow → ProjectModel.user_tables
calc_core/engine/tables.py    # compute_user_tables(model, result) → результат таблиц
```

Окружение вычисления: все строки 4 отчётов по кодам + `N`. Выход:
`CalcResult.user_tables: list[UserTableResult(id, name, rows: [(name, values, error?)])]`.

## 2. Фазы

- [x] **F0.** Пакет `calc_core/formula`: токенизатор, парсер (лимиты), вычислитель,
  функции v1 (+ русские алиасы). Обширные юнит-тесты: приоритеты, broadcast, каждая
  функция, ошибки, лимиты, деление на 0.
- [x] **F1.** Модель `UserTable/UserRow`; `CalcResult.user_tables` + `compute_user_tables`
  в `run()` (после отчётов, ошибки не роняют расчёт); сериализация (в снимок при непустых);
  схема в `CalcResponse`. Тесты.
- [x] **F2.** openapi + `gen:api` + зеркало `model.ts`.

- [x] **F4.** UI-результаты: вкладка «Таблицы» на странице результатов (значения помесячно,
  ошибки строк).
- [x] **F5.** Документация: SPEC (новый § «Язык формул»), ROADMAP, GAP-ANALYSIS (4.1),
  этот чеклист.

## 3. Инварианты

- Формулы читают только результат → методика отчётов не меняется; golden дрейфует только
  снимком `user_tables` при их наличии.
- Вычисление детерминировано (Decimal, CALC_CONTEXT), лимиты защищают от DoS.
