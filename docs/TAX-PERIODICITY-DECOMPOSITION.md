# Периодичность уплаты профильных налогов — план реализации (PP0–PP2)

> Пакет №8 gap-анализа (`GAP-ANALYSIS-PE.md` §2.3): налог на прибыль и НДС платятся по
> своей периодичности (месяц/квартал/год) — влияет на кассу и `B21`. Сейчас всё платится
> в месяце начисления. Реюз `_payment_schedule` (пакет настраиваемых налогов). **Изменение
> методики** → бамп `ENGINE_VERSION`; периодичность по умолчанию `month` → golden без дрейфа.

## 0. Зафиксированные решения (Q1–Q4)

- **Q1. Параметры** — в `ProjectSettings`: `profit_tax_periodicity` и `vat_periodicity`
  (`month | quarter | year`, по умолчанию `month`). Только прибыль и НДС (крупнейшие);
  имущество/налог с продаж остаются помесячными (вне запроса gap).
- **Q2. Только касса.** Периодичность сдвигает **уплату** (C12) в последний месяц периода;
  **начисление не меняется** (I27 в ОПУ, `vat_to_budget` из зачёта НДС — как прежде).
  Неуплаченный остаток (внутри периода + хвост неполного периода) — задолженность в `B21`
  (суммируется с уже отложенным исходящим НДС и настраиваемыми налогами). Реюз
  `_payment_schedule(accrual, periodicity, n)`.
- **Q3. Инертность/совместимость.** `month` → `_payment_schedule` возвращает начисление без
  изменений, задолженность = 0 → числа как сейчас (golden = строка версии). Автоподбор
  финансирования видит сдвиг уплаты во всех итерациях (базовый поток меняется корректно).
  Базы настраиваемых налогов (предварительный прогон) не затрагиваются — периодичность
  профильных налогов чисто кассовая, I26/I27 accrual не меняет.
- **Q4. Версия** — бамп `0.9.34`; ни один семпл не задаёт квартал/год → дифф golden =
  строка версии. B20=B34 держится (начислено − уплачено = прирост B21; property-тест).

## 1. Архитектура

```
calc_core/models/project.py   # ProjectSettings: + profit_tax_periodicity / vat_periodicity
calc_core/engine/taxes.py     # _payment_schedule → экспорт для реюза (уже есть)
calc_core/engine/pipeline.py  # C12: profit/VAT по периодичности; B21 += отсрочки
frontend                      # селекты периодичности в секции «Налоги»
```

## 2. Фазы

- [x] **PP0.** Движок: поля модели, сдвиг уплаты профильных налогов + отсрочка в B21;
  `ENGINE_VERSION=0.9.34` + регенерация golden (дифф = версия). Тесты: квартальная/годовая
  уплата прибыли (C12 в конце периода, B21 между), НДС по периодичности, хвост в B21,
  месяц = текущее поведение, инвариант B20=B34, автоподбор с квартальным налогом.
- [x] **PP1.** API/UI: openapi + `gen:api`, зеркало `model.ts`, селекты периодичности
  прибыли и НДС в секции «Налоги»; проверка сборки.
- [x] **PP2.** Документация: SPEC §11, ROADMAP, GAP-ANALYSIS (2.3), CLAUDE.md, этот чеклист.

## 3. Инварианты

- `month` (по умолчанию) → числа как раньше (golden = строка версии).
- Начислено (I27 / vat_to_budget) − уплачено (C12-часть) = прирост задолженности в B21;
  уплата уменьшает B1; B20=B34 держится.

**Статус: завершено** (0.9.34). v2-направления: периодичность имущества/налога с продаж,
уплата со сдвигом в первый месяц следующего периода (после отчётного), полугодие как период.
