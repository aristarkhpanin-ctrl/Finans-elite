# Чек-лист размещения (Россия)

Что сделать с сервером, прежде чем пускать на него клиентов. Пункты, которые проверяет
сама программа, отмечены «Готовность» — их состояние видно на вкладке «Готовность»
служебного раздела и в `docker compose exec api python scripts/check_readiness.py`
(код выхода 1 при проблеме — годится для ежедневной проверки по расписанию).

Перечень ниже — работа эксплуатации и оператора персональных данных; программа делает
свою часть (роль базы, копии, проверки) и **называет** остальное, но выполнить его за
владельца установки не может.

## 1. Где стоят данные

- [ ] Сервер — в российском дата-центре. Персональные данные граждан РФ записываются,
  систематизируются, накапливаются и хранятся в базах данных на территории РФ
  (ч. 5 ст. 18 152-ФЗ) — это касается и базы, и **резервных копий**.
- [ ] Уведомление в Роскомнадзор об обработке персональных данных (ст. 22 152-ФЗ) подано
  до начала обработки. Категории, цели, основания и место хранения — из
  `docs/PD-INVENTORY.md` (собирается из кода).
- [ ] Уровень защищённости информационной системы персональных данных определён
  (ПП РФ № 1119), меры защиты выбраны (приказ ФСТЭК № 21) — работа специалиста по
  информационной безопасности; что делает код — в разделе «Меры защиты» перечня ПД.

## 2. Доступ снаружи

- [ ] Наружу открыт только HTTPS (443) на обратном прокси с действующим сертификатом;
  порт `8080` сервиса `web` — только для прокси. База и брокер наружу не открыты
  (в `docker-compose.yml` у них нет `ports` — так и оставить).
- [ ] `PUBLIC_URL` — адрес с `https://`: по нему строятся ссылки в письмах и в
  юридических документах («Готовность» → «Публичный адрес»).
- [ ] Вход на сервер — только по ключам SSH; список тех, у кого есть доступ, записан.

## 3. Секреты

- [ ] `.env` лежит рядом с `docker-compose.yml`, права `600`, в репозиторий не попадает.
- [ ] Заданы свои значения: `JWT_SECRET` (длинная случайная строка — без неё сервер в
  продакшене не стартует), `POSTGRES_PASSWORD`, `APP_DB_PASSWORD`, `USAGE_SALT`; ключи
  ЮKassa и пароль почты — когда будут.

## 4. База и изоляция организаций

- [ ] «Готовность» → «Изоляция организаций в базе (RLS)» — в порядке: приложение
  подключено ролью `finans_app` без прав суперпользователя. Суперпользователь обходит
  политики RLS всегда, и изоляция организаций держалась бы на одном фильтре приложения.
  Роль заводит сервис `db-setup` при каждом старте.
- [ ] Суперпользователь `finans` используется только для обслуживания и резервных копий.

## 5. Резервные копии

- [ ] Сервис `backup` работает: «Готовность» → «Резервные копии» — в порядке (копия не
  старше суток, восстановление проверено в срок). Копия — раз в сутки
  (`BACKUP_HOUR_UTC`), хранение `BACKUP_KEEP_DAYS` дней, проверка восстановления — раз в
  `RESTORE_CHECK_DAYS` дней; вручную — `docker compose exec backup sh
  /ops/backup/backup.sh once` и `… check`.
- [ ] **Копия вынесена за пределы сервера** — на другую площадку в России (тоже ч. 5
  ст. 18). Том `backups` лежит на том же диске, что и база: сбой сервера уносит и то и
  другое. Копируется содержимое тома (`finans-*.dump`), лучше — зашифрованным.
- [ ] Место на диске: на время проверки восстановления нужен запас ещё под одну копию
  данных (проверочная база разворачивается на том же сервере).
- [ ] Восстановление в целом проверено хотя бы раз руками: `pg_restore` последней копии в
  новую базу, приложение поднято на ней.

## 6. Обновления и наблюдение

- [ ] Перед обновлением — копия (`backup.sh once`), после — `check_readiness.py`.
- [ ] Обновления операционной системы и образов ставятся по графику.
- [ ] Образ `redis:7-alpine` — решение принято (`docs/registry/README.md`, п. 3): тег
  плавающий, а с 7.4 сервер Redis распространяется под несвободной лицензией.
- [ ] Ежедневная проверка готовности по расписанию (крон с `check_readiness.py`; код
  выхода 1 — повод посмотреть).
- [ ] Трекер ошибок (`SENTRY_DSN`) — свой (например, GlitchTip) на площадке в России
  либо осознанно выключен; персональные данные из событий вычищаются до отправки.
- [ ] Срок хранения журналов сервисов (`docker compose logs`) определён: в журналах
  доступа бывают IP-адреса — это персональные данные.

## 7. Почта

- [ ] Решение по почте принято (`docs/OWNER-SETUP.md`, раздел 1); для домена-отправителя
  настроены SPF, DKIM и DMARC — иначе письма уходят в спам.
