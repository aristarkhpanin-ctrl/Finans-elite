# Актуализация этапов календарного плана — план реализации (SA0–SA2)

> Пакет №8 gap-анализа (`GAP-ANALYSIS-PE.md` §4.6): факт-даты/факт-стоимость этапов и
> отклонения в смете (контроль реализации). Расширяет план-факт (сейчас — только Кэш-фло).
> **Только смета/отображение** — расчёт отчётов не затрагивается; план-числа не меняются.

## 0. Зафиксированные решения (Q1–Q5)

- **Q1. Модель** — факт на самом этапе (когезия с планом): `Stage.actual_start_month`,
  `actual_finish_month`, `actual_cost` (все `Optional`, `None` = не актуализирован).
  Отдельная структура (как у Кэш-фло) не нужна: этап знает свой план и факт.
- **Q2. Смета план-факт** — `StageBudget` дополняется факт-полями + отклонениями:
  `cost_variance = actual_cost − cost` (когда факт задан), `schedule_variance_months =
  actual_finish − plan_finish`. Группы сворачивают факт из потомков: `actual_cost` = Σ
  ненулевых факт-стоимостей потомков (None, если ни у кого нет), `actual_start`/`finish` =
  min/max факт-дат потомков. `Budget.actual_total` — Σ факт-стоимостей листьев.
- **Q3. План не меняется.** Плановые `cost/start/finish/monthly/total` считаются как прежде;
  факт — параллельная аннотация. Движок отчётов (C15/I21/активы) работает на **плане**
  (факт-исполнение — контроль, не пересчёт); методика и golden-числа не затрагиваются.
- **Q4. Golden/версия.** Ни один семпл не использует календарный план → смета в снимок не
  входит (`if result.budget.stages`), дрейфа нет. Факт-поля в `budget_to_dict` — только
  дополнение; бамп `0.9.35` (расширение структуры результата) → дифф golden = строка версии.
- **Q5. API/UI.** `BudgetOut` дополняется факт-полями; смета на вкладке «Календарный план»
  показывает план/факт/отклонение (стоимость и сроки) + DOCX-смета (при наличии факта).

## 1. Архитектура

```
calc_core/models/calendar.py     # Stage: + actual_start/finish/cost
calc_core/reports/result.py      # StageBudget: + факт + variance; Budget.actual_total
calc_core/engine/calendar.py     # compute_budget: свёртка факта (rollup), variance
calc_core/serialize.py           # budget_to_dict: факт-поля
app/schemas.py                   # StageBudgetOut/BudgetOut: факт
frontend                         # смета план-факт в CalendarTab + DOCX
```

## 2. Фазы

- [x] **SA0.** Движок: факт-поля `Stage`, свёртка факта и отклонений в `compute_budget`,
  сериализация; `ENGINE_VERSION=0.9.35` + регенерация golden (дифф = версия). Тесты:
  факт листа → variance, свёртка факта группы, план не меняется, пустой факт инертен,
  смета без календаря пуста.
- [x] **SA1.** API/UI: openapi + `gen:api`, зеркало `model.ts`, факт-колонки в смете
  вкладки «Календарный план» (план/факт/отклонение) + факт-поля этапа; DOCX-смета с
  фактом; проверка сборки.
- [ ] **SA2.** Документация: SPEC §9 (смета/этапы), ROADMAP, GAP-ANALYSIS (4.6),
  CLAUDE.md, этот чеклист.

## 3. Инварианты

- План-числа сметы (cost/start/finish/monthly/total) не меняются; факт — аннотация.
- Отчёты (C15/I21/B15/активы) считаются на плане → методика и B20=B34 не затрагиваются.
- Пустой факт (`None`) → смета как прежде (golden = строка версии).
