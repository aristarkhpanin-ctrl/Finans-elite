# Handoff: «Финанс Аудит» — неоново-фиолетовая ветка системы

Пакет передачи дизайна нового продукта **Финанс Аудит** — due diligence фирмы-цели.
Родственный продукт «Финанс-Элит» (тот же визуальный язык, зелёный → фиолетовый неон).
Целевой репозиторий: `aristarkhpanin-ctrl/Finans-elite` (стек `frontend/` — React 18 + TypeScript + Vite).

---

## 1. Что за продукт

«Финанс-Элит» отвечает инвестору на вопрос **«выгодно ли вкладывать в этот проект»**.
«Финанс Аудит» отвечает покупателю на вопрос **«выгодно ли покупать эту фирму»**.

Пользователь загружает отчётность фирмы-цели (формы 1 и 2, выписки, реестр залогов),
система прогоняет 24 процедуры проверки и возвращает: реестр красных флагов,
нормализованную EBITDA, справедливую цену и вердикт «покупать / торговаться / отказаться».
Сквозной пример во всех макетах — дело № A-2417, ООО «Сибтранс-Логистика».

> Легаси `Audit Expert 3.89` в корне репозитория к продукту отношения не имеет —
> заказчик это подтвердил. Ориентироваться на него не нужно.

## 2. Что такое файлы в этом пакете — ВАЖНО

Файлы `*.dc.html` — **дизайн-референсы, а не production-код**. Каждый открывается в браузере
двойным кликом (рядом должны лежать `support.js` и `Cube Hero (Audit).dc.html`) и показывает
точный внешний вид и поведение.

**Задача разработчика — воссоздать макеты в стеке репозитория**, используя существующие
паттерны (react-router, TanStack Query, AuthContext, Recharts). HTML напрямую в прод не идёт.

Внутри каждого `.dc.html`:
- **разметка** — в блоке `<x-dc>…</x-dc>` (инлайн-стили, шаблонные дыры `{{ … }}`);
- **логика и стили** — в `<script data-dc-script>`, класс `Component`:
  - `THEME()` — полные токены светлой и тёмной темы (идентичны во всех экранах);
  - `DIM()` — размеры для desktop / tablet / mobile;
  - `renderVals()` → объект `s` — готовые CSS-строки каждого элемента. **Главный источник
    точных значений.**

Верхняя панель каждого макета (сегменты «Тема / Устройство / Состояние») — **панель
управления просмотром**, а не элемент продукта. В продукт из неё идёт только наличие
переключателя тем.

## 3. Фиделити

**High-fidelity.** Цвета, типографика, отступы, радиусы, состояния и микро-анимации финальные.
Копировать значения из `renderVals()`.

## 7c. Модель оценки — единые числа во всех макетах

Экран 4, Экран 13 и печатное заключение считают по одному мостику. Если правите
цифры — правьте во всех трёх.

```
Enterprise Value (DCF)              1 767
− Долг и займы                       (831)
+ Денежные средства                   +96
− Миноритарные доли                   (12)
= Цена за 100% доли                 1 020   ← наша оценка
```

Модель продавца даёт EV 1 987 и цену 1 240 — разница 220 млн ₽ и есть цена
выявленных рисков (сумма влияния семи флагов из реестра). Формула чувствительности:
`equity(WACC, g) = 273,9 / (WACC − g) − 747`. Мультипликатор сделки — 6,6× EV/EBITDA
при медиане по отрасли 6,4×. Разброс при отклонении WACC и роста на 1 п.п. — 864–1 209;
Монте-Карло по 10 000 прогонов даёт P5 869, P50 1 020, P95 1 171.

|---|:--:|:--:|:--:|:--:|:--:|
| `project.read` — смотреть дело и заключение | ✓ | · | · | · | · |
| `project.calculate` — запускать скан и пересчёт | — | ✓ | · | · | · |
| `project.update` — загружать документы, править данные | — | — | ✓ | · | · |
| `project.create` — создавать дело | — | — | ✓ | · | · |
| `project.delete` — удалять дело | — | — | ✓ | · | · |
| `member.read` — видеть состав участников | — | — | — | ✓ | · |
| `member.manage` — приглашать и менять роли | — | — | — | ✓ | · |
| `org.manage` — настройки организации и журнал | — | — | — | ✓ | · |
| `billing.manage` — тариф, оплата, реквизиты | — | — | — | — | ✓ |

✓ — право появляется на этом уровне, · — унаследовано.

Подписи на макетах: Наблюдатель / Аналитик / Редактор / Админ / Владелец.
Два запрета из кода отражены в состояниях: владельца нельзя понизить и удалить,
себя удалить из организации тоже нельзя (обе ошибки — 409).

Переключатель организаций в шапке — под `GET /api/v1/organizations`: членство
many-to-many, один пользователь может состоять в нескольких пространствах.

## 7d. Доступность таблиц

Таблицы в макетах собраны на CSS Grid из `<div>`, потому что колонки должны
сжиматься независимо. Скринридер такую конструкцию не считает таблицей, поэтому
роли задаются явно. Эталон — Экран 2, режим desktop; повторяйте его на всех
табличных экранах (2, 9, 10, 13, 14, 17, 20).

```html
<div role="table" aria-label="Сверка отчётности…" aria-rowcount="412" aria-colcount="6">
  <div role="row" aria-rowindex="1">
    <div role="columnheader" aria-colindex="1">Строка отчётности</div>
    <div role="columnheader" aria-colindex="4" aria-label="Расхождение">Δ</div>
    …
  </div>
  <div role="row" tabindex="0" aria-rowindex="2" aria-label="…смысл строки…">
    <div role="rowheader" aria-colindex="1">…</div>
    <div role="cell" aria-colindex="2">…</div>
    …
  </div>
</div>
```

Правила:

- **`aria-rowcount` — полное число строк**, не число отрисованных: при виртуализации
  пользователь должен слышать «строка 40 из 412», а не «из 20».
- **`aria-rowindex` начинается с 2** — первая строка это шапка.
- **Строка фокусируемая** (`tabindex="0"`) и несёт `aria-label` со смыслом целиком:
  «Прочие доходы, строка 2340. По отчёту 61, по проверке 19, расхождение (−42).
  Источник: выписка · 11 мес. Статус: расхождение.» Без этого скринридер читает шесть
  оторванных чисел, по которым нельзя понять, что не так.
- **Символы в заголовках дублируются словом**: `Δ` → `aria-label="Расхождение"`,
  `×` в кратностях → «раз».
- **Фокус видимый**: `outline:none` на строке плюс `inset 0 0 0 2px` акцентом — рамка
  не сдвигает сетку и читается на обеих темах.
- **Статус не только цветом**: чип всегда содержит слово («сходится», «расхождение»,
  «концентрация»), цвет — усиление, а не единственный носитель смысла.
- **Мобильные карточки** доступны сами по себе: подпись над каждым числом
  («Отчёт», «Проверка», «Δ») читается скринридером как обычный текст, роли не нужны.

**Псевдосостояния пишутся литералом.** `style-hover` / `style-focus` / `style-active`
не принимают вычисленных значений — правило собирается один раз при разборе шаблона,
и подстановка из логики даёт ПУСТОЕ правило: ховер и фокус молча перестают работать.
Пишите строку прямо в атрибут. Но одним хексом обе темы не закрыть: неон `#C77DFF`
против белого даёт 2.69:1, а нетекстовому индикатору фокуса нужно 3:1 (WCAG 1.4.11).
Поэтому цвет приходит переменной, объявленной в `<helmet>`:

```css
[data-fa-theme="dark"]{--fa-focus:#C77DFF;}   /* неон на чёрном */
[data-fa-theme="light"]{--fa-focus:#7A2BC4;}  /* 7.07:1 к белому */
```

```html
<div style="…frame…" data-fa-theme="dark">…
  <div role="row" tabindex="0"
       style-focus="background:rgba(199,125,255,.18);box-shadow:inset 0 0 0 2px var(--fa-focus)">
```

Атрибут остаётся статическим литералом, значение — из темы. `outline:none` на строке
допустим только вместе с работающей собственной рамкой: без неё пользователь клавиатуры
теряет фокус совсем.

Клавиатура: `Tab` идёт по строкам (не по ячейкам — 412 × 6 остановок неприемлемо),
`Enter` открывает первичный документ, `Esc` возвращает в таблицу.

## 8. Ключевые паттерны поведения (полностью — Экран 8)

- **Скан** — всегда с номером процедуры («19 из 24»), спиннер без текста запрещён.
- **Сканирующий луч** (`fa-scan`) — фирменная деталь: медленная полоса света поверх
  героев и панелей загрузки. Только тёмная тема даёт ей заметность.
- **Ошибка системы ≠ расхождение в данных**: первая — коралловый баннер с «Повторить»,
  второе — янтарный баннер с влиянием на цену и переходом в реестр флагов.
- **Пустые состояния** — всегда следующий шаг + CTA; куб только в полноэкранных.
- **Деструктив** — кнопка называет объект («Удалить дело»), неон не используется.
- **Права и лимиты** — недоступное показывается приглушённым с объяснением, не прячется.
- **Брейкпоинты**: desktop 1180px, tablet 864px, mobile 402px (боковая навигация
  сворачивается в иконки на 864 и уходит в шапку на 402).
- **Устаревший результат** (`is_stale = updated_at > last_calculated_at`): расчёт остаётся
  на экране, но помечен плашкой и подписан временем — не прячем и не обнуляем.
- **Очередь задач** — четыре статуса `AnalysisJob`: в очереди (с позицией), выполняется,
  готово, ошибка. «В очереди» — отдельное состояние, не бесконечный спиннер.
- **Падение задачи** — не то же, что недоступность ФНС: сохраняем прогресс, даём код
  ошибки для поддержки и продолжение с места остановки.
- **Выгрузка в Excel** идёт в фоне, готовый файл приходит тостом со ссылкой.
- **Дублирование дела** (`POST /projects/{id}/duplicate`) — «{название} (копия)», право
  `project.update`; удаление — `project.delete`, всегда с подтверждением, называющим
  последствие.
- **Таблицы на мобильном** — не горизонтальный скролл, а карточки: строка отчётности превращается
  в карточку с кодом, статусом, тремя числами (отчёт / проверка / Δ) и источником. Эталон —
  Экран 2 в режиме mobile.
