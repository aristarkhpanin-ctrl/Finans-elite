# Пояснительная записка для Claude Code

Прочитай этот файл первым. Он объясняет, что лежит в пакете, в каком порядке это
реализовывать и какие решения уже приняты за тебя. Полная спецификация — в `README.md`
(токены, палитры, паттерны), список расхождений с кодом — в
`ПРОБЕЛЫ-сверка-с-репозиторием.md`.

---

## 1. Что нужно сделать

Воссоздать 17 экранов продукта **«Финанс Аудит»** в репозитории
`aristarkhpanin-ctrl/Finans-elite` (ветка `main`, стек `frontend/` — React 18 +
TypeScript + Vite, `backend/` — FastAPI + SQLAlchemy).

«Финанс Аудит» — новый продукт на той же платформе, что «Финанс-Элит». Кода продукта
в репозитории **нет**: наследуются аутентификация, мультиарендность, RBAC, тарифы,
оплата, очередь фоновых задач, холдинги, экспорт. Всё остальное — новое.

Разница продуктов в одну строку: «Финанс-Элит» отвечает инвестору «выгодно ли вкладывать
в проект», «Финанс Аудит» отвечает покупателю «выгодно ли покупать эту фирму».

## 2. Файлы `.dc.html` — это референсы, не код

Каждый файл открывается в браузере двойным кликом и показывает точный внешний вид и
поведение. **В прод этот HTML не идёт.** Из него берутся значения.

Где что лежит внутри файла:

| Что нужно | Где искать |
|---|---|
| Точные цвета светлой и тёмной темы | метод `THEME()` — два объекта токенов |
| Размеры под desktop / tablet / mobile | метод `DIM()` |
| Готовые CSS-строки каждого элемента | объект `s` в `renderVals()` — **главный источник** |
| Разметка и вложенность | блок `<x-dc>…</x-dc>` |
| Данные примеров | конец `renderVals()` |

Верхняя панель макета («Тема / Устройство / Состояние / Раздел») — **панель просмотра
для дизайнера**, не элемент продукта. В продукт из неё идёт только переключатель тем.

Легаси `Audit Expert 3.89` в корне репозитория к продукту отношения не имеет — заказчик
подтвердил. Не ориентируйся на него.

## 3. Порядок работы

Пять волн. Внутри волны экраны независимы, между волнами — зависимость по фундаменту.

### Волна 1 — фундамент (без него ничего не собрать)

1. **`styles.css` / токены** по `Финанс Аудит - Стиль-гайд.dc.html`. Две темы,
   переключатель с сохранением выбора. Все 17 экранов используют идентичный набор
   токенов — расхождений между файлами нет, можно копировать из любого.
2. **Каркас и навигация** — `Экран 6`. Боковая навигация, брейкпоинты
   1180 / 864 / 402, сворачивание в иконки на 864 и уход в шапку на 402.
3. **Библиотека состояний** — `Экран 8`. Скелетоны, пустые состояния, ошибки, тосты,
   валидация, роль без доступа, лимит тарифа, очередь задач, устаревший результат.
   Это сквозной гайд: все остальные экраны ссылаются на него, а не изобретают своё.
4. **Фирменный куб** — `Cube Hero (Audit).dc.html` → `components/CubeHero.tsx`
   с палитрой пропом. Появляется ровно в четырёх местах (навигация 22–30px, вход и
   сплеш, полноэкранные пустые состояния 96–128px, завершение скана). Больше — нигде.

### Волна 2 — ядро продукта

`Экран 3` (вход, регистрация) → `Экран 1` (риск-скан и вердикт) → `Экран 2` (сверка) →
`Экран 7` (качество прибыли) → `Экран 9` (реестр флагов) → `Экран 10` (обязательства).

Это основной поток пользователя: вошёл → создал дело → загрузил отчётность → увидел
вердикт → разобрал находки.

### Волна 3 — оценка и вывод

`Экран 4` (оценка стоимости) → `Экран 13` (анализ рисков) → `Экран 5` (заключение на
экране) → `Заключение (печать)`.

**Критично:** Экран 4, Экран 13 и печатное заключение считают по одному мостику.
Правишь цифры — правь во всех трёх. Мостик и формулы — в §5 этой записки.

### Волна 4 — организация и деньги

`Экран 11` (организация, роли, журнал) → `Экран 15` (приглашение, профиль, пароль) →
`Экран 16` (тарифы, счёт, ЮKassa).

### Волна 5 — расширения

`Экран 12` (онбординг) → `Экран 14` (группа компаний) → `Экран 17` (план-факт).

## 4. Роли и права — строго по `backend/app/rbac.py`

Это место, где раньше был главный риск: макеты и код расходились. Сейчас сведены.
**Не придумывай свои роли.** Пять ролей с наследованием
`viewer ⊂ analyst ⊂ editor ⊂ admin ⊂ owner`, девять прав:

| Право | viewer | analyst | editor | admin | owner |
|---|:--:|:--:|:--:|:--:|:--:|
| `project.read` | ✓ | · | · | · | · |
| `project.calculate` | — | ✓ | · | · | · |
| `project.update` | — | — | ✓ | · | · |
| `project.create` | — | — | ✓ | · | · |
| `project.delete` | — | — | ✓ | · | · |
| `member.read` | — | — | — | ✓ | · |
| `member.manage` | — | — | — | ✓ | · |
| `org.manage` | — | — | — | ✓ | · |
| `billing.manage` | — | — | — | — | ✓ |

Подписи в интерфейсе: Наблюдатель / Аналитик / Редактор / Админ / Владелец.
Кодовое имя показывается рядом с подписью — так заказчик и разработчик читают одну
матрицу.

Два запрета из кода нужно отразить состояниями (оба отдают 409):
владельца нельзя понизить и удалить; себя удалить из организации нельзя.

Переключатель организаций в шапке — под `GET /api/v1/organizations`: членство
many-to-many, один пользователь может состоять в нескольких пространствах.

## 5. Модель оценки — одна арифметика на три экрана

```
Enterprise Value (DCF)              1 767
− Долг и займы                       (831)
+ Денежные средства                   +96
− Миноритарные доли                   (12)
= Цена за 100% доли                 1 020   ← наша оценка
```

Модель продавца даёт EV 1 987 и цену 1 240. Разница **220 млн ₽** — это цена выявленных
рисков, сумма влияния семи флагов из реестра. Не «дисконт» как отдельная строка мостика,
а разница двух моделей: строки «дисконт за риски» в мостике быть не должно.

Формула чувствительности: `equity(WACC, g) = 273,9 / (WACC − g) − 747`.
Мультипликатор сделки 6,6× EV/EBITDA при медиане по отрасли 6,4×.
Разброс при отклонении WACC и роста на 1 п.п. — 864–1 209.
Монте-Карло, 10 000 прогонов: P5 869, P50 1 020, P95 1 171.

Сквозной пример во всех макетах — дело № A-2417, ООО «Сибтранс-Логистика»,
грузоперевозки, отчётность 2023–2025, покупатель ООО «Инвест-Партнёр».

## 6. Правила, которые легко нарушить

- **Таблицы на мобильном — карточки, не горизонтальный скролл.** Строка превращается
  в карточку с кодом, статусом, числами и источником. Эталоны — Экран 2 (сверка) и
  Экран 13 (сравнение сценариев).
- **Устаревший результат не прячем.** `is_stale = updated_at > last_calculated_at`:
  расчёт остаётся на экране, но помечен плашкой и подписан временем. Пользователь сам
  решает, верить ли ему.
- **«В очереди» — отдельное состояние**, не бесконечный спиннер. У `AnalysisJob`
  четыре статуса: pending (с позицией в очереди) / running / success / failure.
- **Падение задачи ≠ недоступность ФНС.** В первом случае виноваты мы: сохраняем
  прогресс, даём код ошибки для поддержки и продолжение с места остановки.
- **Тариф расширяется только по вебхуку** от провайдера, никогда по редиректу из
  браузера. Пользователь вернулся в кабинет — это ещё не оплата.
- **Отрицательные значения в скобках**, не с минусом: `(831)`, не `−831`.
  Единственное исключение — печатный бланк, где так же.
- **Одна акцентная кнопка на экран.** Второе действие — призрачная кнопка с рамкой.
- **Свечение (`glow`) только в тёмной теме.** На светлой его заменяет тонкая тень.
- **Никаких эмодзи.** Иконки — символьные глифы из макетов (`↻`, `✓`, `—`, `◆`).

## 9. Лендинг — отдельная история

`landing/` — уже готовая боевая вёрстка: HTML5 + LESS (БЭМ) + ванильный JS,
mobile-first, 375 / 768 / 1280. Это **отдельный статический сайт**, не часть
`frontend/src`. Собранный CSS лежит рядом с исходниками, правки — в LESS.

Палитра лендинга **другая**: нейтральное золото `#FFCE3A` вместо продуктового фиолета,
потому что лендинг говорит от имени компании, а не одного продукта. Продуктовые цвета
(фиолет и зелёный) появляются только на карточках платформ. Правила —
в `Финанс - Стиль-гайд лендинга.dc.html` и `landing/README.md`.
