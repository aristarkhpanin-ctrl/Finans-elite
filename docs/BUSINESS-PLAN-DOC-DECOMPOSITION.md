# DOCX-бизнес-план и экспертное заключение — план реализации (D0–D3)

> Пакет №5 gap-анализа (`GAP-ANALYSIS-PE.md` §5.1–5.2): генерация документа бизнес-плана
> (Word/DOCX) и автотекст «экспертное заключение». Продажно-важен: банки/инвесторы просят
> документ, не SaaS-скриншоты. Движок не трогаем; golden без дрейфа (текстовые разделы —
> вне расчёта).

## 0. Зафиксированные решения (Q1–Q5)

- **Q1. Экспертное заключение** — детерминированный автотекст из уже посчитанного:
  `calc_core/review/opinion.py → build_opinion(review, result) → str` (абзацы). Собирается
  из «светофора», топ-находок по severity (с рекомендациями) и показателей (NPV/IRR/PB/
  потребность в капитале). Никакого ИИ — шаблонные фразы над фактами (как PE).
  Поле `opinion` добавляется в `ReviewResponse` (эндпоинт `/review`), показывается в UI
  ревью и вставляется в DOCX.
- **Q2. Разделы бизнес-плана.** `ProjectModel.business_plan: list[PlanSection(title, text)]`
  — плоский список текстовых разделов (резюме, описание рынка, команда…); дерево — v2.
  Текст пользователя, к расчёту отношения не имеет (модель без разделов инертна).
- **Q3. Документ (DOCX, python-docx).** Структура: титул (название, дата, горизонт, движок)
  → экспертное заключение → показатели эффективности (таблица) → пользовательские разделы →
  финансовые отчёты (4 таблицы) → маржа по продуктам и смета этапов (при наличии).
- **Q4. Длинные горизонты.** В документе отчётные таблицы при `n > 24` агрегируются
  **по годам** (потоковые строки — суммы, балансовые — конец года); при `n ≤ 24` — помесячно.
  Ядро не меняется — свёртка на слое генерации.
- **Q5. Эндпоинт.** `GET /projects/{id}/business-plan.docx` → файл (Content-Disposition).
  Право `project.read`. Считает проект на лету (как /calculate, без записи сводки).
