# НМА как класс актива — план реализации (IA0–IA2)

> Пакет №8 gap-анализа (`GAP-ANALYSIS-PE.md` §1.8): нематериальные активы как класс с
> амортизацией. Машинерия активов (capex→C14, амортизация→I17/B10, остаточная→баланс) уже
> есть — нужна **новая категория разноски** остаточной стоимости в `B16` (Другие активы).
> **Изменение методики** → бамп `ENGINE_VERSION`; новая категория не используется семплами →
> golden без дрейфа чисел.

## 0. Зафиксированные решения (Q1–Q4)

- **Q1. Категория** — `AssetCategory.INTANGIBLE = "intangible"`. НМА амортизируется (как
  оборудование, не как земля); остаточная стоимость разносится в **B16 «Другие активы»**
  (единственная свободная статья актива; в B1–B34 отдельной строки НМА нет).
- **Q2. Баланс.** `B16 = nbv[INTANGIBLE]`; B16 входит в `B11` (= B12+…+B16) → B20. Налог
  на имущество (база `B13+B14`) НМА **не облагает** (правильно). Аггрегаты B9/B10 (gross/
  накопл. аморт.) включают НМА как любой амортизируемый актив; инвариант B20=B34 держится
  той же машинерией, что у оборудования (capex↓кассу, nbv↑B16, аморт↓nbv/↑I17).
- **Q3. Реюз.** Этапы-активы календарного плана и выкуп лизинга могут указывать категорию
  `intangible` (та же машинерия). Доинвестирование в НМА работает (слоистая амортизация).
- **Q4. Golden/версия.** `nbv[INTANGIBLE] = 0` для всех существующих моделей → `B16` остаётся
  0 → числа не меняются; ни один семпл не задаёт категорию → дифф golden = строка версии.
  Бамп `0.9.36`.

## 1. Архитектура

```
calc_core/models/common.py    # AssetCategory: + INTANGIBLE
calc_core/engine/pipeline.py  # b16 = nbv[INTANGIBLE] → balance_leaves["B16"]
frontend                      # «НМА» в селектах группы ОС (AssetsTab, CalendarTab)
```

## 2. Фазы

- [x] **IA0.** Движок: категория + разноска в B16; `ENGINE_VERSION=0.9.36` + регенерация
  golden (дифф = версия). Тесты: НМА амортизируется (I17), остаточная в B16, вне налога
  на имущество, продажа/доинвестирование, инвариант B20=B34, категория инертна без НМА.
- [x] **IA1.** API/UI: зеркало (AssetCategory уже строковый enum), «НМА» в селектах группы
  ОС в карточке актива и этапа-актива; проверка сборки.
- [x] **IA2.** Документация: SPEC §9, ROADMAP, GAP-ANALYSIS (1.8, стартовый B16 → отдельно),
  CLAUDE.md, этот чеклист.

## 3. Инварианты

- Без НМА `nbv[INTANGIBLE]=0` → B16=0 → числа как раньше (golden = строка версии).
- НМА: capex→C14 (касса↓), остаточная→B16→B11→B20, амортизация→I17 (прибыль↓)/B10; вне
  базы налога на имущество; B20=B34 держится (та же машинерия, что у оборудования).

**Статус: завершено** (0.9.36). v2-направления: отдельная строка НМА в балансе (не B16),
заполнение стартового B16/незавершённых инвестиций, срок полезного использования НМА
отдельно от ОС.
