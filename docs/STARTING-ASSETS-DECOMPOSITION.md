# Детализация стартовых ОС — план реализации (SO0–SO2)

> Пакет №8 gap-анализа (`GAP-ANALYSIS-PE.md` §1.7): стартовый баланс содержит детальные
> активы, которые можно доамортизировать и продавать. Сейчас стартовые ОС — один агрегат
> `fixed_assets_net` (не амортизируется, продажа не моделируется); детальный актив с
> `purchase_month < 0` не проходит проверку стартового баланса. **Изменение методики** →
> бамп `ENGINE_VERSION`; нет пред-существующих активов → golden без дрейфа.

## 0. Зафиксированные решения (Q1–Q4)

- **Q1. Пред-существующий актив** = обычный `Asset` с `purchase_month < 0` (куплен до старта
  проекта). Реюз всей машинерии активов: капвложений в горизонте нет (оплачен до проекта),
  остаточная стоимость с `t=0` убывает (продолжает амортизироваться), актив можно продать.
- **Q2. Стартовый баланс.** Остаточная стоимость пред-существующих ОС на `t=−1`
  (`cost − ставка·min(−purchase_month, life)`; земля — по стоимости) **сворачивается в
  стартовый актив**: проверка сходимости `актив == пассив` включает её, `opening_balance`
  (t=−1) — тоже. Пользователь балансирует её стартовым капиталом/прибылью (как
  `fixed_assets_net`). Убыль с `t=0` идёт через `nbv` (B14), амортизация → I17 (профиль↓);
  и остаточная (B14), и капитал (B32) падают синхронно → B20=B34 держится.
- **Q3. Инертность.** Активы с `purchase_month ≥ 0` (все существующие + синтетические этапы/
  выкуп) дают нулевую поправку → числа как раньше. Пред-существующие доинвестиции (month<0)
  в v1 в поправку не входят (редкий случай; документировано).
- **Q4. Версия/golden** — бамп `0.9.37`; ни один семпл не задаёт `purchase_month<0` → дифф
  golden = строка версии. Property-инвариант (50 моделей) не генерирует отрицательный месяц
  → не затронут; отдельный тест на пред-существующий актив (амортизация, продажа, инвариант).

## 1. Архитектура

```
calc_core/engine/pipeline.py  # _preexisting_net_open(model): нетто пред-существующих ОС на t=−1;
                              # включить в проверку стартового баланса и opening_balance
frontend                      # подсказка «отрицательный месяц = актив куплен до старта» (AssetsTab)
```

## 2. Фазы

- [x] **SO0.** Движок: `_preexisting_net_open`, включение в проверку стартового баланса и
  `opening_balance`; `ENGINE_VERSION=0.9.37` + регенерация golden (дифф = версия). Тесты:
  пред-существующий актив амортизируется с t=0 и виден в B14; стартовый баланс сходится
  при балансировке капиталом; продажа пред-существующего ОС; земля (нетто=стоимость);
  без пред-существующих — инертно; инвариант B20=B34.
- [ ] **SO1.** UI: подсказка к «Месяцу приобретения» (отрицательный = до старта); проверка
  сборки.
- [ ] **SO2.** Документация: SPEC §9/§14, ROADMAP, GAP-ANALYSIS (1.7), CLAUDE.md, чеклист.

## 3. Инварианты

- Нет пред-существующих ОС → поправка 0 → числа как раньше (golden = строка версии).
- Пред-существующий актив: остаточная (B14) и капитал (B32) убывают синхронно на
  амортизацию → B20=B34 держится (та же машинерия активов).
