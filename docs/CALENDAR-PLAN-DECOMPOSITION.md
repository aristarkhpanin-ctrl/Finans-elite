# Календарный план и бюджетирование по этапам — план реализации (полный объём)

> Исследование — `RESEARCH-CALENDAR-PLAN.md`. Объём выбран **полный (ближе к PE)**:
> иерархия этапов, связи-предшественники (финиш→старт), библиотека ресурсов. Формат —
> фазы K0–K7 (каждая = отдельный коммит), как в `REVIEW-ADVISOR-DECOMPOSITION.md`.

## 0. Зафиксированные решения (Q1–Q6)

- **Q1. P&L обычного этапа.** Поле `amortize_months`: `0` → издержка признаётся сразу (`I21`)
  по мере несения; `>0` → капитализируется в расходы будущих периодов (`B15`) и списывается
  линейно за `amortize_months` от завершения этапа (`I17`-подобно). По умолчанию `0`.
- **Q2. Время.** Месяцы: `start_month` + `duration_months`. Этап занимает `[start, start+duration)`,
  завершение = `start+duration`.
- **Q3. Связи.** `predecessor_id` (финиш→старт). Если задан — эффективный старт =
  `финиш(предшественника) + start_month` (тогда `start_month` = лаг, по умолчанию 0); иначе
  `start_month` — абсолютный. Разрешение — топологически, с защитой от циклов (цикл → старт по
  собственному `start_month`, предупреждение).
- **Q4. Ресурсы.** Библиотека `Resource` (цена ед., задержка оплаты). Этап ссылается на ресурсы
  количеством; стоимость этапа = Σ(кол-во×цена) при наличии ресурсов, иначе прямая `cost`.
- **Q5. Старт производства.** Явный `start_month` в `SalesLine`/`ProductionLine` (опц.); этап
  типа `production` его задаёт. По умолчанию `None` → текущее поведение (старт задан нулями в
  массиве) — golden без дрейфа.
- **Q6. Иерархия.** `parent_id`. Родитель — группа (свёртка для сметы/Гантта); **стоимость несут
  только листья** (у группы собственной стоимости нет — во избежание двойного счёта).

## 1. Модель (calc_core/models/calendar.py)

```
Resource:
  id, name
  unit_price: Decimal
  payment_delay_months: int = 0     # задержка оплаты ресурса → кредиторка B23

StageResource:
  resource_id: str
  quantity: Decimal

Stage:
  id, name
  kind: "expense" | "asset" | "production"
  start_month: int = 0              # абсолютный старт или лаг от предшественника
  duration_months: int = 1
  predecessor_id: str | None = None
  parent_id: str | None = None      # группа (иерархия)
  cost: Decimal = 0                 # прямая стоимость (если нет ресурсов)
  resources: list[StageResource] = []
  cost_timing: "uniform" | "on_finish" = "uniform"
  amortize_months: int = 0          # для expense: 0=сразу, >0=РБП B15 + списание
  asset_life_months: int = 12       # для asset
  asset_category: land|buildings|equipment = equipment
  product_id: str | None = None     # для production

CalendarPlan:
  stages: list[Stage] = []
  resources: list[Resource] = []
```

`CalendarPlan` → в `InvestmentPlan` (рядом с `assets`) либо в `ProjectModel`. Решение: в
`InvestmentPlan.calendar` (раздел «Инвестиционный план» PE объединяет календарь + активы).

## 2. Движок

**Разрешение расписания** (calc_core/engine/calendar.py):
- эффективный старт этапа (рекурсия по `predecessor_id`, мемоизация, защита от циклов);
- финиш = старт + duration;
- стоимость листа = Σ ресурсов или `cost`; у группы = 0 (свёртка — отдельно, для сметы).

**Трактовка стоимости по типам** (распределение по месяцам этапа: uniform или on_finish):
- `expense`: отток `C15` по графику; при `amortize_months=0` — издержка `I21` в те же месяцы;
  при `>0` — капитализация в `B15` (РБП), списание `I17` линейно за `amortize_months` от финиша.
- `asset`: синтетический `Asset(cost, purchase_month=финиш, life=asset_life_months,
  category=asset_category)` → реюз машинерии активов (capex `C14`, амортизация `I17`/`B10`,
  остаточная `B14`) — **приём выкупа лизинга**.
- `production`: задаёт `start_month` продукта `product_id` (гейтирует сбыт/производство).

**Ресурсы**: `payment_delay_months` сдвигает оплату (→ кредиторка `B23`) относительно
признания стоимости — как отсрочка у издержек. (K2.)

Инвариант B20=B34 держится: оттоки финансируются существующей машинерией.

## 5. Инварианты и совместимость

- Пустой `CalendarPlan` (по умолчанию) → нулевое воздействие → **golden без дрейфа чисел**
  (только `engine_version` при первом включении).
- Каждый этап-актив проходит через тот же путь, что плановые активы и выкуп лизинга →
  сходимость баланса гарантирована машинерией.
- Стоимости этапов входят в потребность в капитале; при недостатке денег — автоподбор/займы
  (существующая логика).
