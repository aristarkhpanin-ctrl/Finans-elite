# Исследование: Календарный план и бюджетирование по этапам

> Как это устроено в Project Expert 7.21 и как ложится на наше ядро. Аналог
> `PLAN-REVIEW-ADVISOR.md` — изучение и оценка осуществимости перед разработкой.
> Проприетарный код/ресурсы PE не используются; описывается функционал.

## 1. Что это и зачем

**Календарный план** (раздел «Инвестиционный план» в PE) — встроенный в финмодель модуль
управления проектом на **инвестиционной (подготовительной) фазе**: стройка, закупка и монтаж
оборудования, лицензирование, пуско-наладка. Он описывает подготовку как расписанный набор
**этапов** со стоимостью и сроками и превращает это в:

1. **график инвестиций** — профиль оттоков денег во времени (потребность в капитале);
2. **формирование активов** — этапы капитализируются в основные средства;
3. **сигнал старта производства** — продукт начинает выпускаться по завершении своего этапа.

**Бюджетирование по этапам** = смета проекта, разбитая по этапам с привязкой ко времени
(сколько и когда тратится на каждый этап) — основа плана-факта по этапам в дальнейшем.

## 2. Как устроено в Project Expert (по справке, §4.4 RESEARCH-ProjectExpert)

### 2.1 Этапы
- **Иерархия** (WBS): этап может быть группой из под-этапов; родитель агрегирует срок и стоимость.
- Каждый этап: название, **дата начала + длительность** (дни) *или* фиксированная дата,
  стоимость, ответственный (информационно), статус.

### 2.2 Связи (предшествование)
- Этапы связываются: обычно «финиш→старт» — следующий стартует по завершении предыдущего.
  Так строится диаграмма Гантта; быстрое создание/редактирование связей.

### 2.3 Типы этапов (важно — влияют на расчёт)
- **Обычный**: несёт стоимость в течение длительности.
- **Этап-актив**: по завершении накопленная стоимость формирует **основное средство** (→
  «Список активов»), которое затем амортизируется.
- **Этап «Производство»**: отмечает **старт выпуска** продукта — связывает календарь с
  операционным планом (сбыт/производство продукта начинаются по завершении этапа).
- **Этап с фиксированной датой**: привязан к дате независимо от предшественников.

### 2.4 Ресурсы
- Библиотека ресурсов (материалы/оборудование/труд/услуги) с ценой и **условиями оплаты**.
  Стоимость этапа = Σ(кол-во × цена ресурса). График выплат за ресурсы (предоплата/по
  факту/отсрочка) определяет, **когда** уходят деньги.

### 2.5 Список активов
- Активы, сформированные этапами (или самостоятельные): амортизация, доп. инвестиции,
  переоценка, продажа, НДС.

### 2.6 Как это превращается в бюджет и деньги (суть)
- Стоимость этапа **распределяется по расписанию** → инвестиционные оттоки в подготовительном
  периоде.
- **Этап-актив** → капитализация в ОС (`C14`, далее амортизация).
- **Обычный подготовительный этап** → «Другие издержки подготовительного периода» (`C15`),
  часто как расходы будущих периодов с последующим списанием.
- Сумма за подготовительный период = **стартовая потребность в капитале** (покрывается
  капиталом/займами/автоподбором).
- Выход: **смета по этапам** + **график инвестиций**.

## 3. Как это ложится на наше ядро (что уже есть)

| Элемент PE | В нашем ядре |
|---|---|
| Этап-актив → ОС | **Есть** `Asset` (cost, purchase_month, life, category) + машинерия: capex→`C14`, амортизация→`I17`/`B10`, остаточная→`B14`. Этап-актив = инъекция синтетического `Asset` (**тот же приём, что для выкупа лизинга**). |
| Обычный подгот. этап → `C15` | `C15` («издержки подготовительного периода») **сейчас не используется** (нулевой) — чистая точка входа. |
| Старт производства | Сейчас старт продукта **неявный** — задаётся нулями в начале массива `volume`. Этап «Производство» должен сдвигать старт (rough edge, см. §4). |
| Расписание (Гантт) | Наш движок **помесячный**; PE — по дням. Берём месячную гранулярность (`start_month` + `duration_months`). |
| Сходимость баланса | Оттоки этапов финансируются существующей машинерией (капитал/займы/автоподбор) — инвариант держится. |

## 4. Осуществимость и границы (что берём, что упрощаем — и почему)

**Вывод: осуществимо**, значительная часть переиспользует машинерию активов. Аргументы за
упрощения v1:

- **Месячная гранулярность** вместо дат-по-дням. *Аргумент:* точность до дня косметическая в
  помесячной денежной модели; убирает сверку день↔месяц.
- **Плоский список этапов** в v1 (без иерархии). *Аргумент:* группировка — это свёртка для UI,
  не необходимость расчёта; в v2.
- **Явный `start_month`** у этапа в v1; связи-предшественники (финиш→старт) — v2. *Аргумент:*
  полный граф зависимостей = планировщик расписаний; явные месяцы покрывают большинство планов,
  а «старт = финиш предыдущего» легко посчитать позже.
- **Ресурсы отложены в v2**: v1 — прямая стоимость этапа + тайминг оплаты (равномерно по
  длительности либо разово в конце). *Аргумент:* ресурсы — слой декомпозиции стоимости;
  бюджетный/денежный эффект уже схвачен стоимостью этапа и таймингом.
- **Типы этапов сохраняем**: обычный, этап-актив (реюз `Asset`), производство (старт продукта) —
  именно они влияют на расчёт.

## 5. Предлагаемая модель v1

```
Stage:
  name: str
  start_month: int
  duration_months: int
  cost: Decimal
  kind: "expense" | "asset" | "production"
  cost_timing: "uniform" | "on_finish"     # как распределяется стоимость (по умолчанию uniform)
  # для kind=asset:
  asset_life_months: int
  asset_category: land | buildings | equipment
  # для kind=production:
  product_id: str                          # какому продукту задаёт старт
  # (v2: predecessor_id, resources[], parent_id для иерархии)
```

**Трактовка в движке:**
- `expense` → стоимость распределяется по месяцам этапа → `C15` (отток) + расходы будущих
  периодов `B15`, списываемые за горизонт (амортизация подготовительных затрат, `I17`-подобно).
  *Решение Q1 — см. §6.*
- `asset` → синтетический `Asset(cost, purchase_month = start+duration, life, category)` →
  capex `C14`, амортизация. Реюз приёма выкупа лизинга.
- `production` → задаёт `start_month` связанного продукта (сдвиг массива `volume`). *Решение Q5.*

**Выход (бюджет):** новая секция результата — смета по этапам (стоимость, старт, финиш) +
график инвестиций (Σ по месяцам). Возможен план-факт по этапам (позже).

**UI:** вкладка «Календарный план» в разделе «Инвестиции»: список этапов + **полосы Гантта**
(наш SVG, без сторонних либ) + сводка сметы.

## 6. Открытые вопросы (к решению перед разработкой)

- **Q1. P&L обычного этапа.** Списывать сразу (издержка периода) или капитализировать как
  расходы будущих периодов (`B15`) и амортизировать за горизонт? *Рекомендация:* капитализация +
  равномерное списание (ближе к PE «подготовительный период»); сохраняет сходимость чисто.
- **Q2. Время.** Месяцы (рекоменд.) или дни. → месяцы.
- **Q3. Связи.** Явный `start_month` в v1 (рекоменд.), предшественники в v2.
- **Q4. Ресурсы.** Отложить в v2 (рекоменд.).
- **Q5. Старт производства.** Ввести явный `start_month` в `SalesLine`/`ProductionLine` (этап
  его задаёт) — чище, чем сдвигать массивы. *Рекомендация:* да, явный старт.
- **Q6. Иерархия этапов.** v2 (рекоменд.).

## 7. Черновик плана фаз (при одобрении подхода)

- **K0.** Модель `Stage` + движок: `expense`→`C15`/`B15`, `asset`→синтетический `Asset`,
  `production`→старт продукта. Аналитические + golden-тесты (инвариант B20=B34).
- **K1.** Выход бюджета: секция «смета по этапам» + график инвестиций (result + схема).
- **K2.** API (эндпоинт/поля).
- **K3.** UI: вкладка «Календарный план» (список + Гантт + смета).
- **K4.** Документация (SPEC §9/§новый, ROADMAP), план-факт по этапам — набросок для v2.
