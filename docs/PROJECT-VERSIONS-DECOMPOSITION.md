# Версии проекта и анализ изменений — план реализации (V0–V3)

> Пакет №8 gap-анализа (`GAP-ANALYSIS-PE.md` §4.4): сохранённые версии одной модели и
> сравнение «что изменилось» в данных и результатах. Инфраструктура снимков уже есть
> (финализация: `finalized_model_hash`/`finalized_review`). **Только слой хранения/API/UI**
> — расчётное ядро и golden не затрагиваются.

## 0. Зафиксированные решения (Q1–Q6)

- **Q1. Версия = именованный снимок модели** (ручной, как «сохранённые версии» PE):
  метка + полный JSON модели + сводка расчёта на момент снимка (NPV/IRR/движок).
  Автоснимок при финализации — v2.
- **Q2. Хранение** — новая таблица `project_versions` (org_id для RLS + project_id +
  label + model JSON + created_at + сводка). Лимит **50 версий на проект** (защита
  хранилища): сверх — `409` (без тихого вытеснения). Каскадное удаление с проектом.
- **Q3. Диф — два слоя** (чистые функции, `app/versioning.py`):
  - **модель**: обе модели «расплющиваются» в листовые пути (`operating_plan.sales[0].
    price[3]`), множественный дифф → `added | removed | changed` (path, old, new).
    Длинные неизменные ряды не дают шума; вывод ограничен `N=300` записями (+флаг
    усечения) — защита от гигантских дифов.
  - **результаты**: оба варианта пересчитываются движком, сравниваются заголовочные
    показатели (NPV/IRR/MIRR/PI/PB/DPB/пиковая потребность) — old/new/дельта.
  - Цель дифа: версия ↔ версия либо версия ↔ **текущая рабочая модель**.
- **Q4. Восстановление** — `POST .../versions/{vid}/restore`: модель версии становится
  рабочей (как `update`, статус → draft; гейт финализации сбрасывается).
- **Q5. Права**: создание/восстановление/удаление версии — `project.update`;
  список/чтение/дифф — `project.read`. Изоляция — RLS + фильтр по org_id (как проекты).
- **Q6. Ядро не трогаем**: `ENGINE_VERSION` без изменений, golden без дрейфа. Диф
  результатов только читает `run()`.

## 1. Архитектура

```
app/db_models.py       # ProjectVersion (org_id, project_id, label, model, summary)
alembic/versions/…     # таблица project_versions + RLS-политика (PostgreSQL)
app/crud.py            # create/list/get/delete/count версий
app/versioning.py      # flatten_leaves, diff_models, diff_metrics (чистые)
app/routers/projects.py# POST/GET версий, diff, restore
app/schemas.py         # VersionOut, VersionSummary, VersionDiffOut
frontend               # вкладка/панель «Версии» + просмотр дифа
```

## 2. Фазы

- [x] **V0.** БД: `ProjectVersion` + миграция (с RLS) + crud; чистые диф-функции
  (`app/versioning.py`) + тесты (flatten, added/removed/changed, усечение,
  metric-diff, лимит версий).
- [x] **V1.** API: `POST /projects/{id}/versions` (снимок), `GET …/versions` (список),
  `GET …/versions/{vid}` (модель), `GET …/versions/{vid}/diff?against=<vid|current>`
  (диф модели+результатов), `POST …/versions/{vid}/restore`, `DELETE …/versions/{vid}`;
  openapi + `gen:api`. Тесты API (снимок/список/диф/восстановление/изоляция/лимит).
- [ ] **V2.** UI: панель «Версии» на странице результатов или редактора (сохранить
  версию, список, дифф с текущей, восстановить); vitest.
- [ ] **V3.** Документация: ROADMAP, GAP-ANALYSIS (4.4), CLAUDE.md, этот чеклист.

## 3. Инварианты

- Версии — снимки; исходный проект и его расчёт не меняются при создании версии.
- Диф детерминирован; расчётное ядро и golden не затрагиваются (только чтение `run()`).
- Изоляция арендатора: версия доступна только в своей организации (RLS + фильтр).
